# Написання коментарів

Коментар, надісланий на GitHub, — це Markdown, а голе текстове поле змушує
набирати кожен `**` і `- [ ]` вручну, а потім з’ясовувати в браузері, чи правильно
відобразилася таблиця. Кожне поле застосунку, яке пише на хостинг, тепер — той
самий редактор, з інструментами, які має поле коментаря самого GitHub:

- поле коментаря pull request’а, відповіді в його тредах і коментарі до рядків
  ([Сторінка pull requests](pull-requests.md));
- поле коментаря issue;
- опис нового pull request’а і текст нової issue
  ([Хостинг та pull-реквести](hosting.md)).

![Поле коментаря pull request’а з панеллю форматування і відкритим на «@al» списком людей для згадки](../../screenshots/comment-editor.webp)

## Написати і Попередній перегляд

**Попередній перегляд** показує текст так, як його буде відображено, тим самим
рендерером Markdown, що й у решті застосунку. Він лише для читання; **Написати**
повертає поле з текстом і курсором там, де ви їх залишили, тож ⌘/Ctrl+Z і далі
скасовує те, що ви набрали, перш ніж подивитися.

Вкладки — це список вкладок: коли одна з них у фокусі, ← і → перемикають між ними.

## Панель інструментів

| Інструмент | Клавіші | Що робить |
|---|---|---|
| **Заголовок** | — | Меню H1, H2 і H3 для виділених рядків; вибір рівня, який рядок уже має, знімає його |
| **Жирний** | ⌘/Ctrl+B | `**текст**` |
| **Курсив** | ⌘/Ctrl+I | `_текст_` |
| **Код** | ⌘/Ctrl+E | `` `код` `` усередині рядка; обгороджений блок ```` ``` ````, коли виділення охоплює кілька рядків |
| **Посилання** | ⌘/Ctrl+K | `[текст](url)` — виділена URL стає адресою, інший текст — підписом |
| **Цитата** | — | `> ` на початку кожного виділеного рядка |
| **Маркований список** | ⌘/Ctrl+Shift+8 | `- ` на початку кожного виділеного рядка |
| **Нумерований список** | ⌘/Ctrl+Shift+7 | `1. `, `2. `… на початку кожного виділеного рядка |
| **Список завдань** | — | `- [ ] ` на початку кожного виділеного рядка |

Кожен інструмент — перемикач: застосований до тексту, де він уже є, він його знімає.
Без виділення жирний, курсив, код і посилання вставляють текст-заповнювач і
виділяють його, щоб одразу набрати поверх. Інструмент списку замінює список іншого
виду, а не накладається на нього.

Правки йдуть через власне редагування текстового поля, тому **⌘/Ctrl+Z скасовує
інструмент** так само, як набране слово, а повтор повертає його.

Панель — одна зупинка для Tab; ← → переходять між її кнопками, а ↓ відкриває меню
заголовків. У полі коментаря ⌘/Ctrl+K створює посилання, а не відкриває палітру
команд. На Mac скорочення використовують лише ⌘, тож Ctrl+B, Ctrl+E і Ctrl+K і далі
роблять те, що з ними роблять текстові поля macOS. За розкладки клавіатури з
нелатинськими літерами скорочення слідують фізичним клавішам B, I, E і K.

## Списки

**Enter** у кінці пункту списку починає наступний — той самий маркер, наступний
номер, порожній `- [ ]` для завдання — з тим самим відступом. Enter на пункті, де
після маркера нічого немає, завершує список і прибирає маркер. Shift+Enter —
звичайний перенос рядка.

## Згадки та посилання

**@** відкриває короткий список людей, що звужується під час набору; **#** перелічує
pull request’и та issues за номером і заголовком (`#42` або `#пошук` для слова із
заголовка). ↑ ↓ вибирають, Enter або Tab вставляють, Esc закриває список — лише
список, а не поле чи діалог навколо нього.

Список береться з того, що застосунок уже має, без повторного запиту до хостингу:

| Поле | @ пропонує | # пропонує |
|---|---|---|
| Pull request | Його автора, рецензентів, виконавців і всіх, хто коментував | Відкриті pull request’и та issues репозиторію, як їх завантажено в бічній панелі |
| Issue | Її автора, виконавців і коментаторів | Те саме |
| Новий pull request | Людей, яких читають його списки вибору рецензента й виконавця, та авторів завантажених pull request’ів | Те саме |
| Нова issue | Авторів завантажених pull request’ів та issues | Те саме |

**@** або **#** усередині слова (адреса пошти), `#` заголовка і все, що всередині
коду, лишаються недоторканими.

## Надсилання

⌘/Ctrl+Enter надсилає з будь-якого поля: коментар до pull request’а або issue,
відповідь у треді, коментар до рядка й опис нової issue. Це працює і з вкладок,
панелі інструментів і попереднього перегляду, а не лише з поля. Esc скасовує
коментар до рядка з тих самих місць. **Відповідь у треді** — однорядкове поле, щоб
довге обговорення не обростало панеллю під кожним тредом: Enter надсилає,
Shift+Enter додає рядок (поле росте разом із ним і зі вставленим блоком), а Esc
відкидає набране, спершу запитавши. Вкладок і панелі інструментів у нього немає,
але клавіші форматування та автодоповнення **@** / **#** у ньому працюють, а кнопка
**Відповісти** з’являється, щойно є що надіслати.

## Шпаргалка

**Підтримується Markdown** під кожним полем відкриває на місці шпаргалку: кожен
формат, що для нього набрати, і його скорочення. Esc або клацання деінде її
закриває. Нічого з того, що ви пишете, не зсувається.

Унизу **Відкрити повний посібник** відкриває цю сторінку. Довідник — окрема
вкладка, тож перехід туди веде зі сторінки, де є поле, і ненадісланий текст
пропав би: коли він є — у цьому полі чи в будь-якому іншому на сторінці pull
request’а, — застосунок спершу питає. У діалогах нового pull request’а й нової
issue шпаргалка не має такого посилання, бо довідник відкрився б позаду діалогу.

## Обмеження

- **Без вкладень.** Перетягування файлу чи вставлення зображення в поле нічого не
  вивантажує: GitHub не має публічного API для вкладень до коментарів, тож файл
  нікуди покласти. Вивантажте його на сайті й вставте посилання.
- **Лише ті, хто і що вже завантажено.** @ не шукає серед користувачів хостингу,
  а # — серед усіх issues: людина, яка не брала участі в обговоренні, чи закрита
  issue, яку бічна панель не прочитала, не пропонуються. Ім’я чи номер усе одно
  можна набрати повністю.
- **Немає запропонованих змін, збережених відповідей і вибору емодзі.**
- **Попередній перегляд — це рендерер застосунку.** Він показує Markdown так, як
  його малює застосунок; відображення на хостингу може відрізнятися в деталях
  (власні розширення GitHub, згадки, перетворені на посилання).
- **Попередній перегляд — це відображення застосунку, а не хостингу.** На сторінках
  pull request’а й issue попередній перегляд малює текст так, як опублікований
  коментар буде показано в застосунку
  ([як показуються коментарі](pull-requests.md#як-показуються-коментарі)): той самий суворий профіль,
  збережені переноси рядків і зображення з іншого сайту, що чекає клацання. На GitHub
  опублікований коментар потім малює GitHub, тож розширення, якого застосунок не знає,
  може виглядати інакше. Діалоги нового pull request’а й нової issue використовують
  звичайний попередній перегляд Markdown застосунку.
- Скорочення фіксовані: їх немає в налаштуваннях скорочень, і вони не слідують
  перепризначенню там.
