# 配置档

一个配置档把一份 **Git 身份**（姓名和邮箱）和它的**集成令牌**捆在一起。切换配置档
时两者一起变——提交的作者信息是对的，API 调用用的也是对的账号。

同一台机器上既有工作仓库又有私人仓库，或者你手上有两个 GitHub 账号时，它就派上
用场了。

![一个配置档：一边是 git 身份，另一边是它的集成令牌](../../screenshots/settings-profiles.webp)

## 编辑配置档案，使用配置档案

设置中有两个页面随个人资料而变 —— **个人资料与身份** 和 **已连接的账户**，位于 **你** 分组的顶部，分组标题显示正在编辑的个人资料。其他页面在任何个人资料下都相同，并在页面顶部注明。

**个人资料与身份** 以个人资料卡片开头：头像、名称（可就地编辑）、应用正在使用时显示 *使用中*、选择器和 **新建配置档案**。**已连接的账户** 以同一个选择器开头，显示在 *正在编辑配置文件* 栏中。选择器决定你正在**编辑**哪个个人资料，不会改变应用正在**使用**的那个。两者不同时，会有一条琥珀色横幅提示，并提供 **使用此配置文件** 来切换。这正是最容易把账户关联到错误个人资料的时刻，所以 已连接的账户 会在每张卡片和按钮上都写明个人资料，确认框也会重复。删除个人资料也在同一处，并会先询问。

卡片下方是 git 身份和提交签名。如果打开的仓库以别人的身份提交 —— 它的 git 配置写的是另一位作者 —— 会出现一行提示和 **把身份应用到当前仓库**；两者一致时没有可应用的内容，这一行也不会出现。接着是个人资料头像、**已连接的账户**摘要 —— 每个主机一行，显示 *已连接*、*令牌已过期或出错*、*无法连接* 或 *未连接*，以及在该主机上打开 已连接的账户 的 **连接** 或 **更新** —— 以及该个人资料使用的 AI。

摘要会在每次打开页面或令牌变化时静默检查，不弹出登录窗口，也从不定期轮询。它的结果也供侧边菜单使用：令牌被拒绝或检查失败时，**已连接的账户** 会显示一个小的警告计数 —— 只针对设置已经做过的检查。无法连接的主机不计入，因为令牌可能没问题。

## AI 是共用的

配置档案不需要自己的 AI：一个[通用
AI](ai.md#所有配置档案共用一个-ai) 服务所有配置档案，
只有确有必要时，配置档案才改用自有 AI。这一选择涵盖一切：使用通用 AI
的配置档案，写法也遵循通用 AI 的设置——提交风格、提交的额外规则、仓库聊天。
需要其他风格的配置档案会得到自有 AI，即通用 AI 的一份副本，
之后可以自行修改。这些全都在 **AI** 页面上编辑；
配置档案页面只说明该配置档案使用哪个 AI，并链接过去。

## 每个配置文件有自己的账号

除了令牌，配置文件还可以在 设置 → 已连接的账户 中**关联**机器上已有的登录——来自 git 的
credential helper 或 GitHub CLI。一个关联只属于一个配置文件：新配置文件一开始是
未连接的，已被其他配置文件持有的账号会被拒绝，因此两个配置文件可以并存两个
GitHub（或 Azure DevOps）账号。参见[托管](hosting.md)。

## 按仓库绑定

一个仓库可以**绑定到某个配置档**上，这样对它做后台获取时，用的永远是那个正确的
账号来认证——哪怕你此刻正在看的是属于另一个账号的仓库。

令牌存放在你的[操作系统钥匙串](security.md)里，绝不会进设置文件。
