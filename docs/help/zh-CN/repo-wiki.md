# 仓库百科

把它对准一个仓库，它就会写出一份简短的百科，讲清楚这套代码库是怎么回事。

## 仓库卡片

- 按字节数统计的**语言构成**。
- **技术栈**——框架以徽章形式呈现（Next、Angular、Electron、Tailwind、Django……）。
- 直接从你的清单文件里读出来的**依赖**（`package.json`、`Cargo.toml`、`go.mod`、
  `pyproject.toml`、`pubspec.yaml`、`Gemfile`……），并按架构角色分组。脚手架类的
  东西——类型桩、加载器、lint 插件——会先被过滤掉，而且只有项目真正声明过的包才
  可能出现。
- **一张模块依赖图**，从源码解析而来（JS/TS、Python、Go、Rust、Dart、Ruby、
  C/C++、PHP），并对着仓库自己的文件做解析，所以一个来自外部包的 import 绝不会
  变成一条假的边。

## 写出来的页面

GitHuttBr 会从仓库跟踪的文件里规划出为数不多的几个页面——文档和清单文件优先，然后
是改动最频繁的那些——再依据每个页面所覆盖的文件把它写出来。

**每一句陈述都注明它出自哪个文件**，而没有任何文件能支撑的论断会被驳回，不会发出
来。这些页面是并行写、一次性存的，所以一次失败的生成绝不会把一份好好的百科覆盖
掉。如果这份百科是在一个较早的提交上写成的，它会告诉你。

## 在后台生成

写一份百科要花些时间——每个页面一次模型调用。这次生成属于应用，而不属于页面：离开百科
去别的标签页或仓库，它会继续进行。回来时，页面会显示进行到了哪一步（*正在规划页面…*，
然后每写好一页就显示一页），同时 **生成知识库** 被暂时禁用，这样第二次点击就不会启动
第二次、相互竞争的生成。*知识库已生成* 的提示无论你在哪里都会出现。

**取消** 会让它停下。不会丢失任何东西：只有在所有页面都写完之后，之前的百科才会被替
换，所以被取消的生成会让它原封不动。取消会终止正在进行的请求——HTTP 调用，或者 CLI 账
户的 CLI 进程——但提供商仍可能对它已经生成的 token 计费。

关闭窗口会取消该窗口发起的生成。

## 导出

**导出** 会把整份东西以互相链接的 Markdown 写进 `docs/wiki/`——于是它可以被提交、在
PR 里评审，并在你的代码托管平台上阅读。工具提示会写明它要写入的文件夹。

旁边的文件夹图标可以为这个仓库选择**另一个文件夹**——仓库里的任何文件夹都行，除了根目
录（在那里导出的 `README.md` 会替换掉项目自己的）和 `.git`。再次选择 `docs/wiki` 就
回到默认值。

### 仓库里已有的百科

当这台机器上没有这个仓库自己的百科时——它是在同事的机器上生成的，或者是在重装之前生成
的——页面会改为读取百科文件夹里的那一份，并说明这一点。判断它新旧的依据是其中盖印的提
交：在那个提交上是最新的，之后就落后了。

从文件夹读回的百科不可能有的东西：写它的模型，以及在这个版本开始把技术栈和页面类型盖
印进去之前所做的导出里的这些信息——那些页面会显示为普通模块，没有技术栈卡片。手动编辑
过的页面会显示为已编辑，但它的 **来源** 列表只保留仍按导出的写法写成的那些行。
**重新生成** 会写一份新的，存在这台机器上，此后以它为准。

对读回的百科点 **删除**，会把它从仓库里删掉，所以会先询问。它只删除导出写入的文件——
这些文件带有它的 *Generated by* 标记——文件夹里的其他东西保持不动。已提交的文件可以用
git 找回；未提交的则不能。

看起来像密钥的文件绝不会被发送。
