# 安全与机密

Gitcito **没有后端**。唯一的网络请求发往你的 Git 托管方；如果你打开了 AI 功能，
还会发往你的 AI 供应商。

![安全设置](../../screenshots/settings-security.webp)

## 机密遮蔽

`.env*`、`*.pem`、`*.key`、`id_rsa`、`credentials.*` 这类文件里的值，在差异（对比）、
文件和追溯（blame）视图中会渲染成 `KEY=••••••`，这样屏幕共享或截图就泄露不了它们。
Apple 的签名材料也算：`*.mobileprovision`、`*.provisionprofile`、`*.p12`
以及 App Store Connect 的 `*.p8` 密钥。`*.cer` 不算——证书本就是公开的。

这**只影响显示**：它从不修改文件，也从不改变你暂存的内容。每个视图都有一个眼睛开关
可以显示原值。`.env.example`、`.sample` 和 `.template` 被当作模板，而不是机密。

![一个 .env 文件，所有值都被遮蔽，旁边是显示开关](../../screenshots/secret-masking.webp)

## 在你造成损失之前的防护

| 防护 | 触发时机 |
|---|---|
| **机密文件** | 提交看起来像凭据的东西时——附带一键*忽略并取消跟踪* |
| **大文件** | 提交超大的二进制对象时（阈值在 设置 → 安全 中） |
| **构建垃圾** | 提交 `xcuserdata/`、`DerivedData/` 或 `.DS_Store` 时——同样提供一键*忽略并取消跟踪* |
| **保护分支** | 直接向 `main`/`master` 提交，或强制推送它们时 |
| **已跟踪的机密** | 推送一个*跟踪着*机密文件的仓库时——每个会话警告一次 |

## 操作系统钥匙串

令牌和[保险库](vault.md)条目用你的操作系统钥匙串加密（Electron 的 `safeStorage`），
而不是用设置文件里的某个密钥。

**在你点头之前，什么都不会碰钥匙串。** 在系统自己的权限对话框出现之前，Gitcito 会
先说明要存的是什么、它做不到什么（一个应用只能读回它自己创建的那条记录——你的其他
密码它够不着），以及拒绝也完全没问题：那样令牌只在本次会话的内存中存活，保险库保持
关闭，你也可以稍后在 **设置 → 安全 → 操作系统钥匙串** 里打开它。

全新安装在真正需要存东西之前，会发出**零**次钥匙串调用。

关闭期间，“集成”中的令牌输入框会提示这一点 — *仅保存到你退出 Gitcito 为止：系统钥匙串已关闭。* — 旁边有 **启用** 按钮。无论在那里还是在这里开启，本次会话中已输入的令牌也会一并保存，无需重新粘贴。

### 没有钥匙串的 Linux

在 Linux 上，钥匙串是一个密钥服务——GNOME Keyring 或 KWallet。如果一个都没在
运行，系统仍会“加密”，但用的是一个固定密码，每台机器都一样：令牌和密钥只是被
打乱了，并没有受到保护。设置 → 安全 会在钥匙串状态下方说明这一点——*没有正在
运行的钥匙串……*——这样“钥匙串”这个词就永远不会代表一种并不存在的保护。

为了不让任何新东西落进一个谁都能还原的存储里，没有钥匙串运行时你输入的令牌
**只保留到你退出应用为止**。令牌输入框会这样提示——*仅保留到你退出 Gitcito：
没有正在运行的钥匙串……*——而且没有重试按钮，因为重试没有用；只有钥匙串能解决。
之前保存的令牌仍然可读——你永远不会被挡在外面——清除或替换其中一个，依然会把旧值
从磁盘上删除。两个局限：通用 AI 的密钥不会被移到它的共享位置（每个配置文件继续
读取自己的那份）；保险库仍然保存到基础存储，因为它没有仅限本次会话的模式。
安装或解锁一个钥匙串并重启 Gitcito，才能重新持久保存新令牌。

## 导入设置

**设置 → 导入 / 导出** 可以在机器之间迁移设置、配置文件和主题。默认导出**不含
任何令牌或 API 密钥**，导入这样的文件也绝不会动你已保存的那些——文件里空白的
令牌表示“这个文件里没有”，而不是“删掉我的”。

### 选择导入哪些内容

一个设置文件里有两类东西：跟着*你*走的（配置文件、主题、快捷键），以及只在写出它的
那台机器上才有意义的（你的仓库所在的文件夹、终端的路径）。在一台新电脑上全部应用，
侧边栏就会塞满指向虚无的标签页。所以在你选好文件（如果有密码，再输入密码）之后，
会有一个对话框问你要带入哪几项。在你按下 **导入** 之前什么都不会生效；**取消**
则一切照旧。

![设置 → 数据 → 导入：四项，仓库未勾选，因为它们的文件夹在这里一个都不存在，路径转换已展开](../../screenshots/settings-import.webp)

| 项 | 包含的内容 |
|------|-----------------|
| **配置文件与账户** | 配置文件、Git 身份、集成链接、通用 AI 设置和配置文件图片——如果文件里有，还包括凭据和[保险库](vault.md) |
| **应用偏好** | 主题、语言、快捷键、布局、提交图和图标的颜色 |
| **仓库与工作区** | 标签页、工作区、收藏、别名、标签页图片、每个仓库使用的配置文件、扫描的文件夹，以及各仓库的笔记和 Wiki |
| **本机程序** | 终端、外部编辑器、默认应用以及 AI CLI 的路径 |

每一项都会显示文件里有多少条属于它的内容。没勾选的项在这台机器上原样保留。

**配置文件会与你的合并。** 来自另一台电脑的文件，很少会有这台电脑上的全部配置
文件——在 Linux 笔记本上新加的账户、只存在于 Mac 上的客户配置文件。所以
**配置文件与账户** 会把文件里的配置文件加到你的配置文件里，而不是替换整个列表。
导入之前，这一项会列出每个配置文件以及它将会怎样：

| 标签 | 含义 |
|-----|---------|
| **更新** | 两边都有这个配置文件：文件里的身份、AI 和配置文件图片替换你的，它的服务器加到你的服务器里 |
| **新增** | 只有文件里有：加在你的配置文件后面 |
| **保留** | 只有这台电脑有：原样保留 |

两个配置文件共享同一个 id 时就算“同一个”——每次安装的第一个配置文件都是如此。
没有 id 匹配时，就按名称匹配（忽略大小写和首尾空格），并且该配置文件保留
**这台电脑的 id**：绑定到它的仓库、当前激活的配置文件、它保存的凭据和配置文件图片都继续
关联着。激活的是哪个配置文件不会改变。

**全部替换** 依然在，用于你想原样恢复的备份：只留下文件里的配置文件，只有这台
电脑才有的那些会以删除线标为 **已移除**。这时按下 **导入** 会再问一次，并点出
它们的名字——它们会连同保存的凭据和配置文件图片一起消失，而且无法撤销。选 **全部替换**
时，文件里激活的配置文件会成为当前激活的配置文件。

局限：匹配只按 id 或完全相同的名称——在一边改了名的配置文件会被当作新的，结果
两个都在。匹配上的配置文件会采用文件里的字段，但有三个例外，以免丢掉只有这台
电脑才有的东西：它的 GitHub Enterprise、GitLab 和 Bitbucket 服务器会**加到**
你的里面（两边都有的服务器以文件里的条目为准）；文件里留空的令牌会保留你的——但仅限
同一个实例，所以令牌绝不会被发往另一个 Forgejo、另一个 GitLab 签发方或另一个
Azure 组织；从这台机器的凭据助手借来的登录，仍然属于这台机器。

**默认勾选是根据你的磁盘做出的猜测。** 在显示对话框之前，Gitcito 会检查文件里的
仓库文件夹在这里是否存在。如果一个都不存在，说明文件来自另一台电脑：**仓库** 和
**程序** 初始不勾选，各自附上原因——程序的路径会列出来，让你看出它们属于别处。
如果存在，就是同一台电脑（比如恢复的备份），全部初始勾选，并有一条绿色提示说明。
完全没有仓库的文件则改为按程序路径判断：只有当每个路径在这里都存在时，**程序**
才会初始勾选。

如果检查本身失败了，就不做任何猜测：**仓库** 和 **程序** 初始不勾选、也不给结论，
一个 **重新检查** 按钮会再问一次磁盘，并且在检查成功之前 **仓库** 无法导入。其他
项可以。

**转换路径。** 在一个文件夹缺失的文件上勾选 **仓库**，就会展开一个 **转换路径**
框。左边是文件里这些仓库共同所在的文件夹（`/home/you/code`）；右边是这个文件夹在
这台电脑上的位置，根据你的主文件夹预先填好（`/Users/you/code`）。两边都可以编辑——
猜测可能是错的；Gitcito 找不到共同文件夹时，会把两边都留空让你填写。你输入时，
一个进度条会统计现在有多少仓库在这里找到了文件夹，并列出其中几个——绿色为已找到，
红色为仍缺失。替换时，仓库的别名、标签页图片和配置文件，以及它的笔记、Wiki 和
保险库条目都会一起带过去，什么都不用手动重新设置。

底部会做个总结——*导入 4 项中的 3 项 · 31 个文件夹*（扫描根目录和上一次克隆用的
文件夹也算在内，所以说的是文件夹而不是仓库）——在至少勾选一项之前，**导入**
保持不可用。

**转换什么都没找到时，导入同样不可用。** 勾选了 **仓库**，而新前缀下一个文件夹
都没找到，此时导入会让你的仓库列表变空；请修正路径或取消勾选这一项。

转换的局限：

- 它只是**把一个前缀换成另一个**。在文件里位于其他文件夹下、或者在这里摆放方式
  不同的仓库，都找不到；没有逐个仓库的映射。
- 转换生效时，**只导入转换后有文件夹的仓库**。其余的被略过——不会作为失效的标签页
  加进来——对话框会告诉你有多少个。
- 程序永远不会转换：`/usr/bin/code` 在另一个系统上没有可靠的对应物。让这一项保持
  不勾选，然后在设置里选择它们。
- 清空任意一个前缀，就会按文件里原样的路径导入。

**导入进行中** 对话框无法关闭。如果后面的某一步失败了——仓库笔记、保险库、配置文件图片——
对话框会保持打开，指出是哪一步，**继续导入** 会从那里接着做，不会重写之前的步骤。

### 文件中的凭据

勾选了该选项导出的文件会带有凭据。合并配置文件时总是**添加**凭据：文件里的凭据
归到匹配的配置文件下，替换同一账户的凭据，其他所有已保存的凭据都保留——清掉它们
就和保留你的配置文件相矛盾了。当配置文件选的是 **全部替换** 时，这样的文件还会在
**配置文件与账户** 正下方显示这个选择：

| 选择 | 你已保存的凭据 |
|--------|------------------------|
| **添加到我的** | 文件里的凭据被添加，替换同一账户的凭据；其他的全部保留 |
| **全部替换** | 变得和文件里完全一致——文件里没有的每个已保存令牌和 API 密钥都会被删除 |

这个选择随配置文件一起生效：**配置文件与账户** 未勾选时，不会导入或删除任何凭据。
未勾选该选项导出的文件，不管你勾什么，都没有凭据可提供。按下 **导入** 时，**全部
替换** 会再问一次，说明文件里没有的每个已保存令牌和 API 密钥都将被删除；在那里
**取消** 会让对话框保持原样。

**全部替换需要钥匙串。** 钥匙串关闭或不可用时，旧令牌会留在加密存储里，并在下次
启动时回来，所以 Gitcito 会拒绝：它会说明原因，什么都不导入。已保存的令牌无法读取
期间也是如此：一旦能读取，它们就会回来。**添加到我的** 依然可用，并在本次会话中
保留文件里的令牌。

**局限：** 凭据属于某个配置文件。被导入移除的配置文件，无论你选哪一项，都会带走它
保存的令牌。
