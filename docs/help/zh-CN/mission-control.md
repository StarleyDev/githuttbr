# 任务中心

二十个仓库，而问题永远是同一个：哪一个需要我？

任务中心回答它。**当前工作空间**里的每一个仓库都在同一屏上，按谁真正需要你来排序：

1. **受阻**——一次变基或合并做了一半停在那儿、有冲突、或者仓库根本读不出来。
2. **待同步**——先是要拉取的提交，然后是要推送的提交。
3. **进行中**——未提交的工作、未跟踪的文件。
4. **干净**——安静的那些，待在底部，那才是它们该在的地方。

![每个仓库都在同一屏上，最糟的排在最前](../../screenshots/mission-control.webp)

## 一行能告诉你什么

每一行从左往右读，各列在整个列表中对齐，因此可以像表格一样比较数字：

| 列 | 显示内容 |
|---|---|
| **仓库** | 名称、分组、分支及其上游 —— 没有时以琥珀色显示**无上游**：这样的分支不会被误推送，但也永远不会同步 |
| **最近提交** | 标题和作者：不用打开就知道仓库最近在做什么 |
| **本地** | 冲突 · ↓ 待拉取 · ↑ 待推送 · 已暂存 · 已修改 · 未跟踪 · stash。悬停可查看每个数字统计的是什么 |
| **托管** | 打开的拉取请求（等待**你**审查的以琥珀色显示），以及 HEAD 的 CI。点击数量打开该仓库的**拉取请求**页面，点击 **CI** 打开它的运行记录 |
| **发布** | HEAD 能到达的最新标签，以及它之后又有多少个提交——一个都没有时显示**已是最新**。数量的颜色表示发布落后了多少：5 个提交以内为灰色，20 个以内为黄色，再多为红色，共四个区间，可在[**设置 → 主题 → 发布提示颜色**](themes.md#发布提示颜色)中修改——包括自定义颜色 |
| **活动** | 14 天提交的迷你折线图，以及提交数量 |
| **时间** | 距离最近一次提交和最近一次**获取（fetch）**的时间 |

悬停在状态图标上，可以看到这一行排在这里的原因 ——“2 个待推送 · 1 个未提交”。

显示获取时间，是因为读取这个页面从不执行 fetch：“待拉取”的数量只和最近一次 fetch
一样新。有上游的分支一天或更久没有 fetch，或从未 fetch 时，时间会变成琥珀色 ——
在相信一个 0 之前先 fetch。时间直接从 git 读取，所以在终端里执行的 `git fetch`
也算数。

![设置 → Git 与同步：自动获取旁边的 Mission Control 刷新间隔](../../screenshots/settings-git-sync.webp)

窗口较窄时，所有列都保留，表格在自己的边框内横向滚动。

行末的**打开**显示仓库本身——它的提交图——即使它的标签页上次显示的是点 PR 数量打开的拉取请求列表。

展开一行（点箭头，或按 <kbd>space</kbd>）就能确切看到有哪些提交正等着被推送、哪些文件是脏的。

## 把这张列表用起来

- 顶部那排状态药丸是**筛选器**——点「3 个受阻」就只看那几个。**N 个打开的 PR**
  和 **N 个 CI 失败** 也一样能筛选，下面一行的 **N 个 PR 等待你审查** 也是。
- 可以按**紧迫度**、**名称**或**活跃度**排序。
- **勾选若干仓库**去获取它们，或者只拉取那些落后的（按钮会替你数好个数）。
- 当有跟踪上游的分支一天或更久没有获取时，会出现**获取 N 个过时的**，
  它只获取这些分支 —— 也就是“待拉取”可能不准的那些。
- 只要它开着，每 30 秒自己刷新一次——可在**设置 → Git 与同步 → Mission Control
  刷新间隔**中修改，最少 30 秒。页面关闭时什么都不会运行。

| 按键 | 动作 |
|---|---|
| <kbd>↑</kbd> <kbd>↓</kbd> 或 <kbd>j</kbd> <kbd>k</kbd> | 在列表里走动 |
| <kbd>Enter</kbd> | 打开那个仓库 |
| <kbd>f</kbd> / <kbd>p</kbd> | 获取 / 拉取它 |
| <kbd>space</kbd> | 展开它 |
| <kbd>/</kbd> | 跳到筛选框 |

## 它是一个视图，不是一个标签页

工作空间名字旁边的那个仪表盘图标用来开关它；点任意一个标签页就回到你的工作。它从不给自己添一个标签页，而且它属于你当前所在的那个工作空间——切换工作空间，你拿到的就是那个工作空间的看板。

git 这一侧是**本地**的：每个仓库几条 git 命令，不执行 fetch。**托管**列是唯一与托管平台通信的部分。它以该仓库的配置文件身份、悄悄地向每个仓库的托管平台询问打开的拉取请求和 HEAD 的 CI：对该配置文件没有令牌或关联的托管平台就什么都不显示，也绝不会弹出登录窗口。已经在标签页中打开的仓库不产生任何请求，因为侧边栏已经有它的拉取请求。

一些限制，好让数字被正确解读：

- 无论刷新间隔是多少，每个仓库**最多每 5 分钟**询问一次托管平台（HEAD 移动或 CI 运行仍在进行时会更早）——托管平台的 API 配额与应用的其他部分共用。**刷新**会立即重新询问。
- 托管平台返回的第一页已满时，数量显示为 **30+**；列表页面里有全部。
- 发布列是**从 HEAD 可到达**的最新标签，而不是仓库中最新的标签。在 HEAD 已包含的提交上新建的标签会在两分钟内显示。

获取永远是你主动要求的。
