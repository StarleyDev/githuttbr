# 主题与外观

内置主题——GitHuttBr、Nord、Dracula、Solarized、GitHub、Monokai、Midnight、
Contrast 和 Daltonic——每一套都有浅色和深色两个变体。

![从浅色切到深色](../../screenshots/clip-themes.webp)

- **浅色、深色，或者跟随系统**，即时切换。
- **自定义主题**，以及由一段提示词**用 AI 生成**的主题。
- 可调的**代码字号**。
- 工具栏和侧边栏各分区的**图标颜色**——见下文。
- **图谱的外观** —— 泳道配色、拐角、行密度和线宽，并带实时预览 —— 有自己的页面 **设置 → 图谱**：见[提交图谱](graph.md)。

![主题设置](../../screenshots/settings-themes.webp)

## 图标颜色

一排灰色图标会让获取、推送和贮藏看起来差不多，直到你读了它们的标签。主题标签页
「外观」下的**图标颜色**按每个图标的作用给它上色，让眼睛先于文字找到操作：

| 角色 | 图标 | 采用的主题颜色 |
|---|---|---|
| 接收 | 获取、拉取、远程、工作树 | 主题的青色槽位 |
| 发送、完成 | 推送、待办、议题、发布 | 绿色 |
| 引用 | 分支、本地、标签、拉取请求、里程碑、子模块 | 强调色 |
| 搁置 | 贮藏、弹出、贮藏列表、书签、已固定 | 主题的橙色槽位 |

撤销、重做、工具和设置保持灰色：它们是辅助功能，让它们保持朴素，才能让有颜色的
图标突显出来。

条目很多的列表会一次给整组上色，让一组读起来像一个家族：

- **工具菜单**——时光回溯（Reflog、WIP 快照、时光机、二分查找）为橙色；分支工具
  （吸收、各类雷达、本地 CI、比较）为强调色；每组再各有一色：检视为青色，分支与
  历史为强调色，文件与补丁为绿色，仓库为橙色，密钥与分享为红色。
- **设置页面** —— 布局与终端、工作区 和 AI 用强调色；个人资料与身份、代码分析器 和 环境 用绿色；已连接的账户、Git 与同步 和 数据与备份 用青色；主题 和 图谱 用橙色；安全与确认 用红色。常规、快捷键 和 关于 保持灰色。

没有文字标签的一排图标按钮则反过来——每个按钮都有自己的颜色，以便区分。在
[拉取请求页面](pull-requests.md) 上，页眉按钮依次为：刷新蓝色，AI 评审强调色，在本地预览
青色，前往源分支绿色，前往目标分支橙色（在浏览器中打开仍为灰色）；你自己评论上的 **编辑**
使用强调色，**删除** 使用红色——在那里和 issue 页面上都是如此。蓝色和青色是主题颜色的
混合，所以也会随主题变化。

| 选项 | 你看到的样子 |
|---|---|
| **单色** | 所有图标都是灰色，和有这个选项之前一样 |
| **柔和色调**（默认） | 颜色混入灰色；悬停时显示完整颜色 |
| **全彩** | 颜色本身，衬在同色调的小色块上 |

颜色来自主题——一个重新调整了绿色或强调色的主题，会连图标一起重新上色，自定义
主题和 AI 生成的主题也一样。

限制：只有工具栏的主按钮、侧边栏的分区标题、工具菜单、设置页面，以及拉取请求和 issue 页面
的按钮会上色；其他菜单、分区内的各行和提交图都不会。鼠标悬停的菜单行保持平常的样子，图标
也一样。颜色从来不是唯一的线索——每个图标都保留着它的标签。

## 设置的组织方式

侧边菜单按主题把页面分组：

| 分组 | 页面 |
|---|---|
| **你** | 个人资料与身份 · 已连接的账户 · AI — 前两个编辑标题中显示的个人资料（[个人资料](profiles.md)） |
| **外观** | 主题 · 图谱 · 布局与终端 |
| **行为** | 常规 · Git 与同步 · 安全与确认 · 代码分析器 |
| **系统** | 工作区 · 快捷键 · 环境 · 数据与备份 · 关于 |

常规 只保留与整个应用有关的选项 —— 语言、仓库标签页显示、桌面通知、更新后打开变更日志、关闭时提醒。其余选项都已移到各自所属的页面，页面上的说明会带你过去：

| 选项 | 现在位于 |
|---|---|
| 初始加载的提交数、每次「加载更多」的提交数、滚动时自动加载更多、相对时间、显示头像、使用 GitHub 头像 | **图谱** — 以及原来在 主题 的图谱标签页里的 泳道配色、连线拐角、行密度、节点样式、提交图聚焦、贮藏布局、线条粗细 |
| 自动获取间隔（分钟）、始终创建合并提交、记住冲突的解决方式、外部差异与合并工具、外部编辑器、默认的「打开方式」应用 | **Git 与同步** |
| 强制推送前确认 | **安全与确认** |
| 代码分析器, launch.json | **代码分析器** |
| 文件查看器、让头像动起来、隐藏已完成的待办、按前缀分组 ref | **布局与终端** |

集成 现在叫 **已连接的账户**，数据 现在叫 **数据与备份**。每个选项的作用都没有变，已保存的设置原样保留。按旧名称打开页面的链接仍会打开正确的页面。

## 查找设置

设置分成了许多页面，想找的选项很少恰好在你猜的地方：你知道它存在，却不知道在
哪一页。设置标题栏里、关闭按钮旁边的搜索框，会一次搜遍所有页面。

![在设置中搜索“terminal”](../../screenshots/settings-search.webp)

一边输入，右侧就会按页面分组列出匹配的设置——每一项都带有名称、一行说明和它所在
的页面。侧边栏会把没有匹配的页面调暗，并在有匹配的页面上显示数量。

- 它会匹配设置的名称、说明和页面名称 —— 也包括菜单重新分组前它所在的页面，所以输入“general fetch”仍能找到 Git 与同步 中的自动抓取，输入“integrations”能找到 已连接的账户。不区分大小写和重音，而且输入的每个词都必须出现，所以“terminal font”会缩小到终端的字体设置。
- 搜索同时使用界面语言和英语：即使应用是中文界面，输入“token”或“font”也能找到
  对应的设置。
- 点击一个结果，或按 **Enter** 选第一个，即可打开它所在的页面，滚动到该设置并短暂高亮。
- **Esc** 清空搜索；再按一次 **Esc** 关闭设置。

它搜索的是名称和说明，不是你设置的值。集成页里按主机划分的服务器列表（GitHub
Enterprise Server、自托管 GitLab、Bitbucket Data Center）只会打开集成页面，主机
的标签需要你自己选。单个键盘快捷键没有编入索引——搜索能找到快捷键页面，那里的
编辑器会列出它们。

## 布局

侧边栏可以放在左边或右边，各处面板都能拖动改变大小，侧边栏可以收起来——好让提交
图独占整个窗口，终端的位置也能按仓库分别设置。

同一页面 **设置 → 布局与终端** 还包含标题栏和侧边栏的附加选项 —— **让头像动起来**、**隐藏已完成的待办**、**按前缀分组 ref** —— 以及文件查看器的更改边栏和缩略图。
