# CI 运行

你推送了，然后开始等：切到浏览器，找到仓库，打开 Actions，找到你的运行，打开变红的作业，
滚到日志末尾。**CI 运行** 把这一圈搬到代码旁边。一个页面告诉你每个工作流最近表现如何，
按从新到旧列出远程的运行，并把失败的运行直接打开在出错的测试上——带文件和行号，离编辑器
只有一次点击。重新运行或停止它的按钮就在卡片上。

它用你已经交给 GitHuttBr 的令牌与托管平台自己的 API 通信。你的机器上不会运行任何东西——
那种需求请看 [本地 CI](local-ci.md)。

![CI 运行页面：每个工作流一张卡片，显示其最近的运行；失败和运行中筛选；正在进行的运行的进度；以及一个打开在出错测试及其作业上的失败运行](../../screenshots/ci-runs.webp)

## 打开方式

**工具 → CI 运行…**，或命令面板（⌘K）中的 *CI 运行*。和 wiki、洞察一样，这个页面挂在
仓库的标签页上，读取名为 `origin` 的远程——没有 `origin` 时读取第一个远程。

## 页面显示的内容

| 部分 | 是什么 |
|---|---|
| **工作流卡片** | 每个工作流一张卡片：由什么触发、最近 10 次已结束运行的通过率（90 % 起为绿色，70 % 起为琥珀色，更低为红色）、以彩色方块显示的这些运行——最旧的在左，所以最新的紧挨着“现在”——平均耗时，以及最慢的作业或最近一次运行的结果。点击卡片只列出该工作流的运行；再点一次显示全部 |
| **所有分支 / 当前分支** | 远程上的每次运行，或只看你检出的分支 |
| **失败 / 运行中** | 快速筛选，附带各自会保留的运行数。它们统计的是其他筛选保留下来的部分，所以这个数字就是点击后看到的数量 |
| **筛选** | 按标题、工作流、分支、作者、提交或事件缩小已加载的运行 |
| **运行卡片** | 提交的标题（或工作流名称），然后是分支、工作流和运行编号、触发方式（push、pull request、定时、手动…）、触发者和提交——点击提交即可复制。运行属于某个拉取请求时，**PR #n** 会打开该拉取请求的页面。右侧：当前状态、耗时和距今多久 |
| **正在进行的运行** | *运行中 · 第 3 步，共 5 步*、进度条和目前的耗时。步骤是正在运行的作业的步骤；在没有步骤的托管平台上（GitLab、Forgejo），改为统计作业 |
| **失败的测试** | 失败的运行会自动打开，最新的优先，显示其日志指出的测试：作业、测试、错误的第一行以及 **路径:行号**——点击它或 *在编辑器中打开* 即可跳到那一行。与拉取请求的 [检查标签页](hosting.md#检查标签页) 读法相同 |
| **作业** | 其下是每个作业及其状态和耗时，在有阶段的托管平台上（GitLab、Azure）按阶段分组。*查看步骤和日志* 打开作业的步骤和日志末尾——失败的作业上始终有这个按钮，其他作业在指针悬停时出现 |
| **步骤** | 作业的每个步骤及其状态和耗时——GitHub、Azure 和 Forgejo 会报告；GitLab 没有步骤 |
| **日志** | 已结束作业日志的末尾，保留颜色。只获取最后 512 KB——失败所在之处——省略了开头时页面会注明 |

只要页面上有排队或运行中的内容，列表就会每 15 秒重新询问托管平台，同时询问打开的运行和
每个正在进行的运行的作业——步骤计数就来自这里；耗时每秒跳动。如果两分钟的回应都没有新内容
——比如某个运行在等待部署审批——它会放慢到每分钟一次，一有变化就立即恢复。全部结束的列表
在你按刷新之前什么也不问，窗口隐藏时也不会发出任何请求。

托管平台发来的没有标题的运行——每条 GitLab 流水线、定时的 Azure 构建——如果其提交在图中，
就以该提交的主题命名，从本地仓库读取，不花任何代价；否则以编号命名。

## 重新运行、取消、启动

| 按钮 | 何时出现 | 会发生什么 |
|---|---|---|
| **重跑失败项** | 运行失败或被取消 | 只重新运行没有通过的作业 |
| **重新运行**（↻） | 运行已结束，在 GitHub 上——指针悬停时出现在卡片上 | 每个作业都重新运行 |
| **在浏览器中打开** | 指针悬停在卡片上 | 托管平台网站上的该运行 |
| **取消** | 运行在排队或运行中 | 会先询问：进行中的作业被中断，其已完成的工作会丢失 |
| **运行工作流** | 托管平台支持手动启动 | 选择工作流和分支；它会像该分支被推送一样启动，几秒后出现在列表中 |

各托管平台允许的操作：

| 托管平台 | 列表与作业 | 步骤 | 日志 | 全部重跑 | 重跑失败项 | 取消 | 手动启动 |
|---|---|---|---|---|---|---|---|
| **GitHub**（及 Enterprise Server） | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓——工作流需要 `workflow_dispatch` 触发器 |
| **GitLab**（及自托管） | ✓——流水线，按阶段分组的作业 | — | ✓ | — | ✓（*Retry*） | ✓ | ✓——在分支上运行 `.gitlab-ci.yml` |
| **Azure DevOps** | ✓——构建，按阶段分组的作业 | ✓（任务） | ✓ | — | ✓ | ✓ | ✓——仓库的任意构建定义 |
| **Forgejo / Gitea** | ✓ 在提供 Actions 运行 API 的服务器上 | ✓ | ✓ 服务器向令牌提供时 | — | — | — | — |
| **Bitbucket** | — | | | | | | |

## 图中的徽章

同样的 CI 也会以小徽章出现在图中每个提交旁：绿色、红色，或运行中时显示时钟。悬停查看作业；
点击打开托管平台的页面。徽章来源：

| 托管平台 | 来源 |
|---|---|
| GitHub | 提交的 check run——任何向 GitHub 报告的 CI，不只是 Actions |
| GitLab | 提交的状态，包含每个流水线作业。手动作业（比如部署）不会让徽章一直停在时钟上 |
| Azure DevOps | 仓库最近的 100 次构建，按提交匹配 |
| Forgejo / Gitea | 提交的组合状态——Forgejo Actions 和任何外部 CI |
| Bitbucket Data Center | 提交的构建状态 |

每个回答都会被记住——包括“这里没有 CI”——只有当答案可能已变化时才会再次询问某个提交：
运行中每 45 秒一次，结束后每 10 分钟一次，对从未有过 CI 的提交则越来越少。这样繁忙的图也能
保持在托管平台的每小时限额之内。

## 限制

- **卡片只知道页面列出的运行。** 也就是当前分支筛选下的最近 50 次运行——很少运行的工作流
  可能不到十个方块，切换到当前分支会重新计算每张卡片。最慢的作业要等页面读过某个已结束运行
  的作业后才出现（它自动打开的那个失败运行就够了）；在那之前，卡片显示最近一次运行的结果。
- **失败的测试是从日志文本中读出的。** 能识别 Vitest、Jest 和 pytest；其他任何运行器、
  构建错误或被截断的日志只显示作业列表。运行器写在检出目录之外的路径无法打开。
- **PR #n 取决于托管平台给出的信息。** GitHub 只为来自同一仓库（而非 fork）的运行列出拉取
  请求；GitLab 会为合并请求流水线给出，Azure 会为 PR 构建给出。Forgejo 的运行没有链接。
- **日志只是末尾，而且只在作业结束后才有。** GitHub 和 Forgejo 在作业完成后才提供其日志；
  运行期间页面显示的是推进中的步骤，而不是输出。GitLab 和 Azure 会提供运行中作业到目前为止
  的日志——重新打开即可读到更多。
- **令牌需要 CI 权限。** GitHub 细粒度令牌列出运行需要 *Actions: read*，重新运行、取消或
  启动需要 *Actions: write*；经典令牌需要 `repo`。GitLab 令牌列出需要 `read_api`，按钮需要
  `api`。Azure 令牌需要 *Build: read*（按钮需要 *Build: read & execute*）；没有时页面和徽章
  保持为空，而不是报错。
- **Azure 徽章只回溯 100 次构建。** 更早的提交没有徽章，但 CI 运行页面仍会列出它的构建。
- **Azure 的重新运行是“重试失败项”。** 它适用于带阶段的 YAML 流水线；经典流水线可能会拒绝，
  页面会显示托管平台的回应。
- **启动工作流时不会询问输入参数。** 带有无默认值必填输入的 GitHub 工作流或 GitLab 流水线
  会被托管平台拒绝，并附带其自己的消息。
- **Forgejo 只读，而且只支持较新的服务器。** 较旧的 Forgejo 和 Gitea 服务器没有列出运行的
  API；页面会说明该托管平台不受支持，而图中的徽章仍通过提交状态工作。令牌看不到的仓库会显示
  为访问错误，而不是“不受支持”。
- **Bitbucket 没有运行页面。** 在 Data Center 上，CI 是只报告状态的外部系统（Jenkins、
  Bamboo…）——那个状态就是图中的徽章。不支持 bitbucket.org Pipelines。
- **只读一个远程。** 页面读取 `origin`；fork 的其他远程上的运行不会列出。
