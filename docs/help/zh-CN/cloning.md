# 克隆

**新建仓库 → 克隆**，或者 `⌘K` → *克隆*。粘贴一个 URL，或者登录 GitHub、GitLab、
Bitbucket 或 Azure DevOps，从你自己的仓库列表里挑一个——所选[配置档](profiles.md)
的令牌只用于这次克隆，用完即弃，绝不会写进 `.git/config`。

选一个父文件夹和一个名字；字段下方那行会明明白白地告诉你仓库最终会落在哪里。
已经存在的文件夹会被拒绝，而不是往里面混着放。

## 一次克隆多个仓库

配置一台新机器，或者把团队名下的所有服务都拉下来，以前意味着每个仓库都要打开一次
这个对话框。在托管平台标签页里，勾选你想要的每个仓库前的复选框，或者点 **全选显示的**
把筛选匹配到的全部拿下。点击某一行（而不是它的复选框）仍然只选中那一个。

勾选了不止一个时，对话框会把它们全部克隆到同一个父文件夹下，每个各放进一个以仓库
命名的文件夹。开始之前会先列出这些路径。如果有两个同名（`org-a/app` 和
`org-b/app`），两者的文件夹名都会带上所有者（`org-a-app`、`org-b-app`），而不是抢同
一个文件夹。

![克隆对话框的 GitHub 标签页：勾选了三个仓库，父文件夹下列出了它们将落到的文件夹，以及一个「克隆 3 个仓库」按钮](../../screenshots/clone-multi-select.webp)

这一批会直接进入角落里的托盘。同时运行三个克隆，其余的以 *排队中* 等待；每个都有自
己的取消按钮。每个仓库一完成就会在标签页里打开。

限制：
- 批量时 **要检出的分支** 会被隐藏：分支名在不同仓库之间毫无意义，所以每个仓库都用
  自己的默认分支。其他高级选项（部分克隆、浅克隆、单分支、子模块）对全部生效。
- 多选只在托管平台标签页里可用。URL 标签页只接受一个 URL。
- 一个失败不会让其他的停下。文件夹已存在的仓库会带着自己的错误失败，其余的继续。

## 高级——把克隆收窄

**高级** 下面的东西默认全是关的：不去动它，你得到的就是一次普通的、完整的克隆。
它真正派上用场的地方，是那些「完整」意味着二十分钟外加好几个 GB 的仓库。

![展开「高级」的克隆对话框：部分克隆、浅克隆、单分支、子模块和分支选择器](../../screenshots/clone-advanced.webp)

| 选项 | git 做了什么 | 代价是什么 |
|--------|---------------|---------------|
| **部分克隆** | `--filter=blob:none` | 完整历史，但不含文件内容。数据块按需到达，所以打开一个旧文件需要联网。 |
| **浅克隆** | `--depth=N` | 只存在最新的 N 个提交。追溯（blame）、日志、二分查找和范围差异都会在切口处戛然而止。 |
| **只要一个分支** | `--single-branch` | 其他分支留在远程，直到你去获取它们。 |
| **克隆子模块** | `--recurse-submodules` | 每个子模块也一并检出——现在多花点时间，以后少一堆空目录。 |
| **要检出的分支** | `--branch <name>` | 从该分支开始，而不是远程的默认分支。 |

**先考虑部分克隆，再考虑浅克隆。** 部分克隆保留每一个提交——历史仍然可以搜索，
只有文件内容是惰性获取的。浅克隆是真的把历史丢掉了：`git log` 到切口就结束，
追溯也看不到切口之前的东西。如果你克隆一个大仓库是为了在里面干活，通常你想要
的是部分克隆。

浅克隆是可以撤销的：在[终端](terminal.md)里执行 `git fetch --unshallow`，历史
就补回来了。

### 挑选分支

直接键入分支名，或者按 **列出分支** 去问远程都有些什么（`git ls-remote --heads`），
然后从下拉列表里选。那是一次网络往返，而且只在你按下按钮时才发生——你打字的
过程中什么都不会查询。

如果列举失败了——私有 URL 还没有令牌、拼错了、没网络——该字段就退回成一个普通
的文本框，而克隆本身会把真正的错误报给你。

### 关于这两个标志的两点说明

- **`--depth` 隐含了 `--single-branch`。** 在浅克隆里，不勾选 *只要一个分支*
  才是在要求把其他分支也拿回来（`--no-single-branch`），这也是它下面的提示文字
  会跟着变的原因。
- **克隆本地文件夹**通常会完全忽略 `--depth`，因为 git 会给对象库做硬链接，而
  不是去获取。所以当你要求对一个本地仓库做浅拷贝时，GitHuttBr 会改用 `file://`
  URL 来克隆，你要的深度就是你拿到的深度。

## 进度、后台运行与取消

进度条如实转述 git 报告的内容：统计、压缩、接收、解析、检出。某个阶段如果报不
出总量，显示的会是一条不确定进度的条，而不是一个编出来的百分比。

大仓库的克隆要好几分钟，以前在对话框外误点一下，这些时间就全白费了。现在关闭对话框
——**在后台运行**、`Esc`、✕ 或者点击外面——只会把它藏起来：克隆继续进行，并挪到右下
角的一张小卡片上，进度条还是同一条。这期间你可以再开始另一个克隆；每个都有自己的卡片。

![角落里的克隆托盘：三个克隆分别在接收、解析和统计，第四个在排队，每个都有自己的取消按钮](../../screenshots/clone-tray.webp)

选错仓库了？对话框里的 **取消克隆**，或者卡片上的 ✕，会停止 git 并删除写了一半的文件
夹。其他东西一概不碰——这个文件夹在克隆开始前并不存在，这一点一开始就检查过。取消的
克隆无法续传；重新开始就是从零开始。

完成后，新仓库会在一个标签页里打开，并固定到你克隆时所用的那个配置档上，不管对话框
是否还开着。

克隆在应用内部运行，所以退出 GitHuttBr 会让它们停下。退出不会等清理完成，所以写了一半
的文件夹可能会留下来——再往那里克隆之前先把它删掉，因为对话框会拒绝已存在的文件夹。
