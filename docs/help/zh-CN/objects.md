# 对象浏览器

git 素有复杂之名。这名声几乎全部来自一件事：从来没人给你看过那个模型——**四种对象，加上指针**。一旦你能点开一个提交、落到它的树上、并发现你的文件*就是*一个 blob，只不过被某棵树赋予了一个名字，那些高层命令就不再是魔法了。

`⌘K` → **对象浏览器**。这个页面上没有任何东西能改动哪怕一个字节——它背后的每一次调用都是读操作。

![main 指向的提交：从分支走来的路径、它指向什么，以及提交在模型中的位置](../../screenshots/objects.webp)

## 四种对象

| 对象 | 是什么 | 知道什么 |
|--------|----|-------|
| **blob** | 一个文件的*内容* | 什么都不知道。不知道自己的名字，不知道路径，也不知道历史 |
| **tree** | 一份目录清单 | 名字、模式，以及每个子 blob 或子树的 sha |
| **commit** | 一张快照 | 它的树、它的父提交、作者、提交者、消息 |
| **tag** | 一个附注标签 | 它指向的对象、打标签的人、一条消息 |

让大多数人吃惊的是第一行。**blob 没有名字。** 你历史中任何位置上内容完全相同的两个文件，就是同一个 blob，只存了一份。名字住在指向它的那棵树里——这正是为什么 git 跟踪的是内容而不是文件，也是为什么重命名是被*检测*出来的，而不是被记录下来的。

一个**引用**——`refs/heads/main`、`refs/tags/v1.0`、`HEAD`——不过是一个装着 sha 的文件。「分支很便宜」这句话的全部内涵，就在这里。

## 走一走

![从提交走到 src/：文件夹在前，每种模式都写明含义](../../screenshots/objects-tree.webp)

左栏列出所有引用，按 git 的方式分组：HEAD（在分支上时带 `→ main`）、分支、标签和
远程，每组带数量；远程默认折叠。方形标记是指向提交的引用，绿色圆形是**附注**标签。
筛选框会同时收窄所有分组。点击一个引用即可来到它指向的对象；从它出发走下去时，
这一行一直保持高亮。

从那里开始，处处都是门：

- **提交**显示它**指向**什么——根树（带条目数）和每个父提交（带标题）——然后是作者和
  提交者（相同时写*与作者相同*），以及消息。
- **树**是一张名称、模式、对象、大小的表，文件夹在前。每种模式都写明含义：*文件*、
  *可执行*、*文件夹*、*符号链接*、*子模块*。文件夹显示包含多少项，符号链接显示指向哪里。
- **blob** 带行号显示文本（大文件只显示开头），是二进制时会直接说明。经由树到达时，
  会有一条横栏说明它在那里叫什么——*在提交 07c6f3d 中名为 src/app.ts，模式 100644
  （普通文件）*——并附有查看文件历史的链接。
- **附注标签**指向它所命名的对象，并记录打标签者。

![一个 blob、树给它的名字，以及它在模型中的位置](../../screenshots/objects-blob.webp)

### 路径

修订输入框下方的横带就是你走过的**路径**：
`分支 main → 提交 07c6f3d → 根 → src/ → app.ts`。提交的树是**根**；文件或文件夹
沿用你点击那一行的名字。点击任意一项即可回到那里。输入修订、选择一个引用，或点选
**打开**旁边的示例，都会开始一条新路径。

**后退**和**前进**像浏览器一样在你打开过的一切之间移动：后退之后，前进可以回去，
直到你从那里打开了新东西。修订输入框跟着你走，所以 `main:src/app.ts` 随时可以复制。

### 颜色

每种对象无论出现在哪里都保持同一种颜色——徽章、路径项、卡片、行：提交用主题的强调色，
树用黄色，blob 用蓝色，标签和引用用绿色。对象标题下方有一句话说明这种对象*是什么*。

### 你在模型中的位置

面板底部的横条是 git 的链条——**ref → commit → tree → blob**，附注标签时在 ref 和
commit 之间多一个 **tag**——屏幕上当前的种类会以*你在这里*高亮。

## 输入一个修订版本

这个输入框接受 `git rev-parse` 接受的一切，而这也正是它从一个浏览器变成一种学习方式的地方：

| 输入这个 | 得到 |
|-----------|--------|
| `HEAD` | 当前提交 |
| `HEAD~3` | 往回数三个提交 |
| `HEAD^{tree}` | 那个提交的树，剥出来的 |
| `HEAD:src/app.ts` | 直接拿到该路径的 blob |
| `v1.0^{}` | 一个附注标签所指向的东西，而不是标签对象本身 |
| `a1b2c3d` | 任何对象，按 sha 找——缩写也行 |

树列表里的模式数字值得认一认：`100644` 是文件，`100755` 是可执行文件，`040000` 是子树，`120000` 是符号链接，`160000` 是子模块的 gitlink——而最后这一个，就是一个子模块所存储的全部内容。

## 值得知道的限制

- **只读，而且是故意的。** 这里没有任何可以用来写的东西。手工造对象是一项 `git hash-object` 的练习，那属于终端。
- **大的 blob 会被截断**，只保留前 200 KB——足够看清它是什么，又不至于把窗口卡死。
- **大小是对象的内容大小**，也就是 `git cat-file -s` 报告的那个数，而不是它打包之后在磁盘上的开销。要看后者，见[仓库维护](maintenance.md)。
- **不可达的对象仍然是对象。** 把 `git fsck` 悬垂报告里的一个 sha 粘进来，它就会打开，而这往往是「在决定要不要恢复之前，先看看那个丢失的提交里装了什么」的最快办法。
- **子模块行无法打开。** 它的 gitlink 指向另一个仓库的提交，而本仓库没有它。
- **计数和链接目标有上限。** 子文件夹超过 300 个的树会不带计数地列出它们，且只有前
  50 个符号链接显示目标。
- **路径随对话框结束。** 关闭后，下次会重新从 HEAD 所在分支开始。
