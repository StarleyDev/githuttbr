# 编辑任意提交

错别字在三周前的一个提交里。常规的修法是交互式变基：停在那个提交上，编辑，继续，
然后祈祷。GitHuttBr 的修法是：右键点击提交，**编辑此提交**，改好文字，完成。提交
详情面板里的钢笔按钮打开的也是同一个编辑器。

![正在编辑一个历史提交](../../screenshots/commit-edit.webp)

## 它做什么

选中任意一个属于 `HEAD` 祖先的提交 — 历史是否线性都无所谓。编辑器在中间窗格打开，取代
提交图的位置 — 也就是冲突解决器和文件查看器打开的地方 — 并占满整个窗口的宽度和高度。
按 **Esc** 或点击标题栏上的 **×** 即可关闭。切换到另一个仓库标签页再回来，你的编辑不
会丢失；带着未应用的编辑关闭时会先询问。

标题栏写明这个提交 — 短哈希、标题、作者和时间 — 一旦你改了什么，一个黄色标签就会统计
**未应用的更改**：提交信息算一项，每个编辑过的文件各算一项。

### 提交信息卡片

提交信息拥有和[提交编辑器](committing.md)相同的工具：摘要前的 **类型 ▾** 按钮、带长度计数（*56/72*）的摘要和下方的描述、箭头后面的样式行（范围、工单编号、提交样式）、gitmoji 选择器、共同作者、根据该提交自身 diff 的 AI 生成，以及 lint 提示。提交信息在加载时被拆开——第一行成为摘要，其余成为描述——改写时再用一个空行拼回去。把旧的 `add retry` 改成 `fix: add retry`，只需在类型按钮里选一项。

提交信息一旦与原始版本不同，卡片就会标上 **已修改**，旧标题以 *之前：…* 的形式留在描述下方，**恢复原样** 会把摘要和描述都还原。

### 文件卡片

提交的文件连同状态字母一起列出；每个你改过的文件都带一个圆点。选中一个文件，即可按它在该提交中的样子编辑。编辑器上方的开关在 **编辑** 和 **与原始版本比较** 之间切换，后者显示该文件从提交中的内容到你编辑后文本的 diff — 与应用其他地方相同的 diff 视图。

**添加文件** 从该提交自身的快照中打开一个提交没有改动过的文件：输入路径的一部分并选中它。编辑之后，改写后的提交也会改动这个文件。它在列表中以 **+** 标记。

![将编辑过的文件与提交中的原始版本比较](../../screenshots/commit-edit-compare.webp)

### 将会发生什么

卡片旁边的面板（窗口较窄时在卡片下方）显示改写会波及的提交链：被编辑提交之上的每一个提交，从 `HEAD` 往下，最底部是被编辑的提交本身以及其中会改变的内容。

1. **预览级联**会把被编辑提交之上的每一个提交*在内存中*重放一遍（一串
   `merge-tree` 拣选 — 没有检出，没有工作区，没有 ref）。随后链中的每个提交都会说明
   它是 **可无冲突重放**，还是在某个具名文件中 **有冲突**，所以在**任何东西真正移动
   之前**，你就知道这次编辑是干净地传播下去，还是会与后来的改动相撞。之后再做任何编辑，
   这些判定都会清空；**再次预览** 会重新运行。
2. **改写历史**才是动真格的：同一条链用底层命令构建出来，然后分支用
   `reset --keep` 移动过去 — 你未提交的改动会被一并带上，否则重置中止，什么都没有
   发生。执行前会先拍一份[守护快照](recovery.md)，**撤销** 则会恢复原来的提交链。

当该提交已经在远程上时，一条黄色提示会写明远程分支，并说明这意味着什么：下一次推送必须强制推送。另一条提示说明有多少个提交会得到新的哈希。

每个被重放提交的作者信息和日期都保持不变；变的只有哈希 — 这正是改写历史的含义。

## 范围内的合并

![编辑两个合并之下的提交——级联会重放它们](../../screenshots/commit-edit-merges.webp)

提交与 `HEAD` 之间存在合并提交时，编辑不再被禁用。级联重放合并的方式，是把它的
**记录结果** — 该合并当初实际提交的那棵树，连同冲突的解决方案一起 — 重新应用到改
写后的父提交上，因此当年手工做出的解决方案会原封不动地在改写中幸存下来。没有
rerere，没有重新合并，没有工作区：与级联其余部分相同的内存内底层命令，而且两个父
指针都会保留。同样包含被编辑提交的旁支分支会被改写并重新指向；不包含它的分支则身
份不受任何触碰。侧面板中的一条提示会说明范围内带有多少个合并，链中的合并提交会显示
一个合并图标。

诚实的告诫：重放的合并只能和它记录的结果一样好。如果你的编辑与该合并自己解决过的
那些行相撞，预览会像任何其他冲突步骤一样变红 — 不做任何猜测。

## 级联发生冲突时

某个后来的提交改动了你正在编辑的那些行。预览会在该提交上标出冲突文件，把它之上的提交
标为未重放，**改写历史** 保持禁用 — 绝不会出现只应用了一半的情况。与变基不同，编辑器
不会中途停下来让你解决冲突：要么换一种改法，要么用[交互式变基](rebase.md)正面解决冲突。

## 限制

- **提交必须是 `HEAD` 的祖先。** 未合并的旁支分支上的提交没有通往当前分支的路
  径可供重放。
- 二进制文件和超过 2 MB 的文件会显示但不可编辑。
- 已经推送到远程的提交也可以编辑，但你的下一次推送将不得不是**强制推送** — 编辑器
  会在你做出这个决定之前发出警告。
- 提交中被删除的文件无法编辑（没有内容可编辑）。
- **添加文件** 只能打开提交快照中已存在的文件；它不能创建全新的文件、删除文件，也不能
  改动符号链接或子模块。
