# 按仓库的设置

工具栏工具旁边那个齿轮，打开的是属于**这个**仓库的设置，而不是应用的设置。

![按仓库的设置](../../screenshots/repo-settings.webp)

头部说明你即将修改的是哪个仓库：名称、文件夹、当前分支、主远程（有 `origin`
时即为它）及其所在主机，以及几个计数。分支数来自已加载的列表。保险库计数只在
你打开 **保险库** 之后才出现，因为读取保险库会询问系统钥匙串，而打开设置不应
如此。没有提交数：统计一段很长的历史本身就是一次 git 调用，头部不值得为此付出。

页面位于侧边导航中，分为三组：

| 分组 | 页面 | 内容 |
|---|---|---|
| 仓库 | **常规** | 显示名称、配置文件、受保护分支、标签页图片和从列表移除 |
| 仓库 | **项目配置** | 此仓库在 `.githuttbr.json` 中[携带的规则](repo-config.md)，以及检查它们的 doctor |
| 仓库 | **信息** | 关于此仓库的自由笔记和字段，保存在本地 |
| 安全 | **保险库** | 此仓库的[保险库](vault.md)条目 |
| 活动 | **指标** | 你在 GitHuttBr 中做过的事，在本地统计 |
| 活动 | **洞察** | [历史仪表板](insights.md) |
| 活动 | **操作历史** | 你打开过的仓库中，随时间变化的提交及其作者 |
| 活动 | **日志** | 操作日志：GitHuttBr 在这里运行的每条 git 命令及其结果 |

操作日志是诚实的那一个：当某件事表现得古怪时，它会给出确切的命令和确切的错误，这样一份缺陷报告就能带上事实，而不是形容词。

## 常规

每项设置是一行：左边是它的作用，右边是控件。按下 **保存** 之前不会存储任何内容。

| 行 | 作用 | 存储位置 |
|---|---|---|
| **显示名称** | 标签页和列表上的名称。磁盘上的文件夹永远不会改名；留空则使用文件夹名称 | GitHuttBr 设置，本机 |
| **配置文件** | 此仓库的标签页处于活动状态时切换到的身份、令牌和 AI。**自动** 跟随当前配置文件 | GitHuttBr 设置，本机 |
| **受保护分支** | 在直接提交或强制推送到这些分支之前发出警告 | 仓库的 git config |
| **标签页图片** | 标签页上的小图片，见下文 | GitHuttBr 设置，本机 |

当仓库带有 `.githuttbr.json` 时，常规页顶部的提示会说明这一点，并链接到
**项目配置**。这些规则随仓库传给每个克隆者；提示下方的各行只属于你自己。

**从列表移除…** 会把仓库从[仓库](repositories.md)中移除。它会先询问，而问题会
说明它不做什么：磁盘上的文件夹不受影响，已打开的标签页仍然打开。再次打开该
仓库即可将它放回列表。

## 标签页图片

打开十个标签页时，开头相同的名称——`api`、`api-gateway`、`api-docs`——
很难分辨。标签页上的一张小图比文字更容易找到。

在 **常规** 中点击图片输入框，会列出仓库自身的图片（PNG、JPEG、GIF、WebP、
SVG、ICO、BMP 和 AVIF），每张都带缩略图，名称像 logo 或 icon 的文件排在最前。
输入即可筛选（`logo dark` 会找到 `assets/logo-dark.png`），用方向键移动，
按回车选择；也可以手动输入路径。路径按 **相对于仓库根目录** 保存，因此无论
文件夹位于何处，图片都会跟随仓库。

标签页显示什么是整个应用的设置，位于 **设置 → 常规 → 仓库标签页显示**：

| 选项 | 标签页显示 |
|---|---|
| **图片和名称**（默认） | 用图片代替文件夹图标，后面是名称 |
| **仅名称** | 文件夹图标和名称，与未设置图片时相同 |
| **仅图片** | 只有图片；名称移到提示框中 |

需要了解的限制：

- 列表包含 git 能看到的文件——已跟踪和未跟踪的，不含被忽略的——一次最多
  40 个；输入即可找到其余的。被忽略的图片仍可手动输入路径。
- 超过 1 MB 或无法读取的图片显示为灰色，无法选择：20 像素的图标用不着更多。
- **没有** 图片的仓库无论选哪个选项都始终显示名称——空白的标签页无法辨认。
- 如果路径 **失效**——文件被删除、改名、不是图片或过大——标签页会静默地改为
  显示名称，此设置页会在路径下方显示警告。其他地方不会提示。
- 图片每个会话只读取一次。如果用同名文件替换了图片，重新打开此设置页即可
  重新加载。
- 该设置保存在本机的 GitHuttBr 设置中，而不在仓库里，因此队友不会继承它。
