# ブランチの整理

チェックアウトしたプルリクエストは、どれもローカルブランチを残していきます。PR が
マージされ、サーバーがそのブランチを削除しても、ローカルのものは残ります — ずっと。
数百回レビューすると、ブランチ一覧はほとんどが不要なブランチになり、生きている
ものを探すにはそれらをすべてスクロールして通り過ぎなければなりません。

ブランチの整理は、作業がすでに別の場所で安全なローカルブランチを一覧にし、失う
ものがないものにチェックを付け、元に戻せる 1 回の操作で削除します。「別の場所」とは、
最後のフェッチ時点のリモート追跡ブランチと、既定のブランチのことです。

![整理ダイアログ: 消滅・マージ済み・squash マージ済みのブランチにチェック、ここにしかない作業は除外](../../screenshots/branch-cleanup.webp)

## 使い方

1. ツール → **ローカルブランチを整理…**（または <kbd>⌘K</kbd>）。
2. 最後のフェッチが古ければ、先に **フェッチして prune** を押します。prune 付きの
   フェッチが走るまでは、サーバーが削除したブランチもここでは生きているように
   見えます。
3. チームがプルリクエストを squash マージしているなら、**squash マージを確認** を
   押します（後述）。
4. チェックを確認して **削除**。確認は 1 回だけで、何本のブランチが消えるかと、
   ほかのどこにもないコミットを持つブランチの名前をすべて示します。

削除は、元に戻す履歴が 1 つだけの 1 回の操作です: **元に戻す** は、削除した各
ブランチを指していたコミットにそのまま作り直し、upstream（`branch.<name>.remote`
と `.merge`）も戻します。その後、同じ名前のブランチが別のコミットに現れていた場合
— 同じ PR をもう一度チェックアウトした — 元に戻す操作はそれに触れず、削除した
ほうをその隣に `<name>-restored-<short sha>` として戻し、その旨を伝えます。

成功メッセージと元に戻す履歴は、各ブランチを指していたコミットと一緒に一覧にします
（`feature/x (was abc1234)`）。`git branch -D` が出力する形です: 元に戻す履歴は
アプリが開いている間しか残らず、この 1 行があればブランチを手で作り直せます。

## ブランチが一覧に載る理由

| チップ | 意味 |
|---|---|
| **消滅** | サーバーが削除した upstream を追跡しているブランチ — マージ済みプルリクエストのいつもの痕跡です。 |
| **マージ済み** | 上のコミットはすべて既定のブランチに入っています。ツールチップがそれを持つコピーを示します — ローカルにしかなければ `main (local, not pushed)`。 |
| **squash マージ済み** | **squash マージを確認** で見つかったもの: 内容は既定のブランチにあり、個々のコミットはありません。 |
| **放置** | 選んだ月数（既定は 3）の間コミットがありません。**放置されたブランチも表示** にチェックしたときだけ載ります。 |
| **N 件のコミットはここにしかありません** | どのリモート追跡ブランチにも既定のブランチにもないコミット。ブランチを削除すると、それらも消えます。 |
| **コミットなし** | 既定のブランチの先端をちょうど指しています — おそらく作ったまま使っていません。 |

「マージ済み」は、既定のブランチのリモート側のコピー（`origin/main`）と、ローカルの
コピーの両方に対して判定します — 1 か月誰もプルしていないローカルの `main` でも、
その間のマージを隠すことはできません。

## squash マージ

squash マージは、プルリクエストの変更を `main` に 1 つの新しいコミットとして
置きます。ブランチ自身のコミットは届きません。git から見ると、そうしたブランチは
放棄された作業に見えます: **消滅** で、*N 件のコミットはここにしかありません*。

独自のコミットを持つ消滅ブランチが一覧にあると、**squash マージを確認** は別の
問いを立てます: このブランチを `main` にマージしたら何か変わるか? すべてに対して
メモリー上で `git merge-tree` を 1 回実行し — チェックアウトもインデックスも
使いません — マージしても `main` のツリーがまったく変わらないブランチには
**squash マージ済み** のチップが付き、マージ済みと同じくチェックされます。確認では、
内容は `main` にあり、コミットはないと伝えます。

確認は削除の瞬間にロックの下でもう一度行われます: もう通らないブランチは削除されず、
拒否されます。

## チェックされるもの、決してされないもの

ダイアログを開いたときにチェックされるのは、**消滅またはマージ済み** で **独自の
コミットがない** ブランチ — 確認後は squash マージ済みのものも。**消滅 + マージ済みを
選択** でその選択に戻せます。

自動ではチェックされず、**表示中をすべて選択** でも決して選ばれないもの: ここにしか
ないコミットを持つブランチ。1 行ずつチェックしてください。すると確認は赤くなり、
コミット数と一緒にそれを示します。放置だけのブランチと、既定のブランチの先端にある
ブランチもチェックされません。選択に一覧が表示していない行 — フィルターで隠れた
もの、または最初の 400 行より後ろのもの — が含まれる場合は、確認がその数を伝えます。

削除は、ブランチごとに、確認で示したちょうどの数の固有コミットだけを受け付けます。
その時点でそれより多い場合 — あるいは **やり直す** で、元に戻した後に増えていた場合
（たとえば prune がリモートのコピーを消した）— は拒否して残し、成功とは言わずに
そう報告します。

決して一覧に載らず、求められても削除が拒否するもの:

- 現在のブランチ;
- どこかのワークツリーでチェックアウトされている、またはリベース中のブランチ;
- 既定のブランチ;
- [保護されたブランチ](repo-settings.md)。[リポジトリ設定](repo-config.md) の
  `release/*` のようなパターンも含みます。

リモートは何も変わりません。削除するのはローカルブランチだけです。

## 制限

- **squash マージは確認するまで git には見えません。** **squash マージを確認** を
  しないと、squash マージ済みのブランチは **消滅** と *N 件のコミットはここにしか
  ありません* で表示され、チェックされません。
- **squash の確認は見逃すことがあります。** 答えるのは「この内容はもう `main` に
  あるか?」です。その後 `main` が同じ行を再び変えた場合や、マージ時に squash を
  編集した場合は、マージで何かが変わるため、ブランチはチェックされないままです。
  内容を失う形で誤って「はい」と言うことはありません: 内容は定義上 `main` に
  あります。[コンフリクトレーダー](conflict-radar.md) と同様に、`git gc` が片付ける
  ばらばらのツリーオブジェクトを書き込みます。
- **フェッチしていないリモートは古いままです。** 「消滅」は最後のフェッチから
  来ます。**フェッチして prune** をしないと、1 時間前にサーバーで削除された
  ブランチもまだ生きて見え、新しいマージもまだ `origin/main` に入っていません。
- **放置は日付にすぎません。** 3 か月動きがなくても、作業が安全かどうかは何も
  分かりません。だから放置の行は決してチェックされません。
- **「別の場所」は最後のフェッチ時点のリモート追跡参照です**。いまのサーバーでは
  なく、タグも含みません。タグだけが保持するコミットは固有として数え、ほかの人の
  リモートブランチにあるコミットは数えません。
- 固有コミットの数は 500 で止まり、*500+* と表示します。確認の合計は下限です —
  *少なくとも N* — 積み重なったブランチはコミットを共有するためです。
- 元に戻す操作はブランチとその upstream を復元しますが、reflog やほかの
  `branch.<name>.*` 設定は復元しません。
- 長い一覧では、ダイアログは最初の 400 行を表示します。残りはフィルターで見つかります。
  **消滅 + マージ済みを選択** は、表示の有無にかかわらずすべての行に適用されます。
