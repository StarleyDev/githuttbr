# ワークツリーとサブモジュール

## ワークツリー

ワークツリーとは、同じリポジトリの 2 つ目のチェックアウトを、それ専用のフォルダに
置いたものです。だから `feature/x` を置いたそのままの状態に保ちながら、`main` を
覗きに行けます。スタッシュは要りません。

- サイドバーからワークツリーを作成・削除できます。**ダブルクリック** すると、その
  ワークツリーが独立したタブとして開きます。右クリックには *ワークツリーを開く*、
  *フォルダーで表示*、削除があります。
- ローカルブランチを右クリック → **ワークツリーで開く** で、隣のフォルダに 1 つ作り、
  タブとして開きます。
- 1 つのブランチが同時に居られるワークツリーは 1 つだけなので、別のワークツリーが
  持っているブランチのチェックアウトは成立しません — git は *already used by
  worktree at …* と断ります。GitHuttBr はその代わりに連れて行きます。ブランチの
  メニューは *`x` をそのワークツリーで開く* と表示し、行をダブルクリックすると
  失敗する代わりにそのワークツリーのタブが開きます。

### ワークツリーの手入れ

先月作ったワークツリーは忘れがちで、片付けのときに疑問が出てきます。作業が残っているか、フォルダはまだあるか。各行が、聞く前に答えてくれます。

| 行の表示 | 意味 |
|---|---|
| **●3** | そのワークツリーに未コミットの変更があるファイルが 3 つ |
| **↑2 ↓1** | そのブランチが upstream より 2 コミット先行し、1 コミット遅れている |
| 🔒 | ロック中 — カーソルを合わせるとロック時の理由が表示されます |
| **見つかりません**、名前に取り消し線 | フォルダがなくなり、git には記録だけが残っています |

![ワークツリーの欄：未コミットの作業と先行コミットがあるワークツリー、見つからない
もの、ロック中のもの、そして見出しの消しゴム](../../screenshots/worktree-care.webp)

数値はセクションを開いたとき、そのワークツリーのコミットが動いたとき、ウィンドウにフォーカスが戻ったときに読み込まれます。更新のたびではありません。それぞれが別フォルダでの `git status` だからです。

行を右クリックすると:

| 操作 | 内容 |
|---|---|
| **ワークツリーをロック** | git（やほかのクライアント）による prune・移動・削除を防ぎます。理由（*外付けドライブ上* など）を入れると鍵アイコンに表示されます。常に接続されていないメディア上のワークツリー向けです。 |
| **ワークツリーのロックを解除** | その逆です。元に戻すと同じ理由で再びロックされます。 |
| **ワークツリーを移動…** | フォルダを移動し、git のリンクを両側とも更新します。ロック中やタブで開いている間は使えません。タブとそのレイアウトはパスで記憶されるため、タブが何も指さなくなるからです。先にタブを閉じてください。元に戻すと元の場所へ戻ります。 |
| **ワークツリーを削除** | まず git に何が失われるかを確認します。クリーンなものには通常の確認が出て、元に戻すと同じブランチ・同じフォルダで作り直されます。未コミットの変更があるものには別の確認 *破棄して削除* が出てファイル数を示し、元に戻せません。 |
| **移動したフォルダを再接続…** | *見つかりません* の行だけ。フォルダの移動先（ファイルマネージャーで移動した場所）を指定すると、git が `git worktree repair` でつなぎ直します。 |
| **見つからないワークツリーを整理** | 見つからない行があるとき、セクション見出しに出る消しゴムボタンも同じです。`git worktree prune` を実行します。 |

これらの操作が**しない**こと:

- **ワークツリーの削除は無視ファイルも消します** — `.env`、`node_modules`、ビルド出力。git はこれらを変更として数えないため、「クリーン」な確認でも注意が表示され、元に戻しても復元されません。
- **整理は git の記録を消すだけです。** 消すファイルはありません（フォルダはもうないため）。ロック中のワークツリーは飛ばされます。外したドライブ上のロック中のものは、削除されたものとまったく同じに見えるからです。
- ロックは git クライアント間の約束であり、ファイルの保護ではありません。git 以外のものがフォルダを消すことは防げません。
- メインのワークツリー（リポジトリそのもの）はロック・移動・削除できません。
- ワークツリーを削除してもブランチは消えません。不要ならブランチ一覧から削除してください。

### ヘッダーでワークツリーをグループ化する

ワークツリーのタブは `ルート · ブランチ` というラベルで開くので、すぐに幅を取ります。

**グループに入れたプロジェクトは、そのワークツリーも迎え入れます。** リポジトリ —
またはそのワークツリーのどれか — がすでにグループに入っていれば、新しいワークツリーは
チェックを入れなくてもそのグループの中、その隣に開きます。ワークツリー追加の
ダイアログはどのグループかを示すだけで、ブランチのメニューの **ワークツリーで開く** も
確認なしに同じことをします。あとから **最近使ったもの** やフォルダから開いた
ワークツリーも同じグループに入ります。単独にしたいときは、チップをグループの外へ
ドラッグしてください。

単独のタブで開いているリポジトリなら、ワークツリー追加のダイアログで **同じルート
リポジトリを共有する worktree をグループ化するか提案する** にチェックを入れます
（既定はオフ、codegraph のオプションと同じく記憶されます）。ルートが単独のタブで
開いていれば **グループ名** 欄が現れ（ルートのフォルダ名が入っています）、両方が
新しいグループに入ります。ファミリーのどれも開いていなければ、ワークツリーが自分の
タブで開くとだけ示します。グループ内では、どのリポジトリのものかをグループがすでに
示しているので、チップは末端の名前（`main`、`feature/x`）だけに縮みます — フルの
`ルート · ブランチ` 名がよければ、設定 → レイアウトとターミナルの切り替えで残せます。
この提案がまとめるのは同じルートを共有するワークツリーだけで、無関係なリポジトリを
一緒にすることはありません。

**ワークツリーのタブを見分ける。** リンクされたワークツリーはリポジトリの 2 つ目の
チェックアウトなので、そのままではタブがリポジトリ本体のものとまったく同じに見えます。
そこでワークツリーのタブには、フォルダアイコンの代わりに緑の **フォーク** が表示され
（画像のタブでは画像の隅に小さなフォーク）、ツールチップには置かれているフォルダと
ともに *… のワークツリー* と表示されます。右クリックすると **メインのリポジトリ … を
開く** があり、メインのチェックアウトがすでに開いているタブを前面に出すか、なければ
開きます — ワークツリーがグループに入っていれば、そのグループの中に。ワークツリーを
どう開いたかにかかわらず働きます。ファミリーから、**リポジトリを開く** から、スキャン
した一覧から開いた場合も同じで、サブモジュールのワークツリーはそのサブモジュールを
指します。制限：この印はチェックアウトがどこにあるかを示すもので、ブランチを示すもの
ではありません。bare リポジトリのワークツリーには、開くべきメインのチェックアウトが
ないので印が付きません。また、シンボリックリンクのフォルダ経由で開いたメインの
リポジトリはすでに開いていると認識されないため、メニューは実際のパスでもう一度開きます。

## サブモジュール

サブモジュールの追加、更新（init とチェックアウト）、URL の同期、削除ができ、それぞれの
状態がその場でわかります。

| 状態 | 意味 |
|---|---|
| **同期済み** | 親が記録しているコミットでチェックアウトされている |
| **変更あり** | 別の場所でチェックアウトされているか、作業ツリーが汚れている |
| **未初期化** | 記録はあるが、一度もチェックアウトされていない |
