# オブジェクトエクスプローラー

git は複雑だという評判があります。その評判のほとんどは、モデルを一度も見たことが
ないところから来ています。**4 種類のオブジェクトと、ポインタ**。コミットをクリック
してそのツリーに着地し、自分のファイルが実はツリーに名前を付けてもらった blob *その
もの* だとわかった瞬間、磁器（porcelain）は魔法ではなくなります。

`⌘K` → **オブジェクトエクスプローラー**。このページは 1 バイトたりとも変更できま
せん — 背後の呼び出しはすべて読み取りです。

![main が指すコミット: ブランチからの経路、指す先、そしてモデルの中でのコミットの位置](../../screenshots/objects.webp)

## 4 つのオブジェクト

| オブジェクト | 正体 | 知っていること |
|--------|----|-------|
| **blob** | ファイルの*内容* | 何も。名前も、パスも、履歴も知りません |
| **tree** | ディレクトリの一覧 | 名前、モード、そして子の blob やツリーそれぞれの sha |
| **commit** | 1 つのスナップショット | そのツリー、その親、author、committer、メッセージ |
| **tag** | 注釈付きタグ | 指しているオブジェクト、タグを付けた人、メッセージ |

ほとんどの人にとって意外なのは最初の行です。**blob には名前がありません。** 履歴の
どこにあろうと内容が同一の 2 つのファイルは同じ blob であり、保存されるのは一度きり
です。名前はそれを指すツリーの側にあります — だから git はファイルではなく内容を追跡
するのであり、だからリネームは記録されるのではなく検出されるのです。

**ref** — `refs/heads/main`、`refs/tags/v1.0`、`HEAD` — は sha を書いただけのファイル
にすぎません。「ブランチを切るのは安い」という話は、これで全部です。

## たどり方

![コミットから src/ まで: フォルダーが先、各モードは言葉で説明](../../screenshots/objects-tree.webp)

左の列には、git と同じ分け方ですべての ref が並びます: HEAD (ブランチ上なら
`→ main` 付き)、ブランチ、タグ、リモート。各グループに件数が付き、リモートは
最初は折りたたまれています。四角い印はコミットを指す ref、丸い緑の印は
**注釈付き**タグです。フィルターはすべてのグループを一度に絞り込みます。ref を
クリックすると、それが指すオブジェクトが開きます。そこから歩いている間、その行は
強調されたままです。

そこから先は、すべてが扉です:

- **コミット**は、何を**指す**かを示します — ルートツリー (項目数付き) と各親
  (件名付き) — 続いて作成者とコミッター (同じなら*作成者と同じ*)、そしてメッセージ。
- **ツリー**は名前・モード・オブジェクト・サイズの表で、フォルダーが先です。各モードは
  言葉でも示されます: *ファイル*、*実行可能*、*フォルダー*、*シンボリックリンク*、
  *サブモジュール*。フォルダーは項目数を、シンボリックリンクはリンク先を示します。
- **blob** は行番号付きで本文を表示します (大きいものは先頭だけ)。バイナリなら
  そうはっきり伝えます。ツリー経由で来た場合は、そこでの名前を示す帯が出ます —
  *コミット 07c6f3d では src/app.ts という名前、モード 100644(通常のファイル)* —
  ファイル履歴へのリンク付きです。
- **注釈付きタグ**は、名前を付けたオブジェクトを指し、タグ作成者を記録します。

![blob、ツリーが与えた名前、そしてモデルの中での位置](../../screenshots/objects-blob.webp)

### パス

リビジョン欄の下の帯が、たどってきた**パス**です:
`ブランチ main → コミット 07c6f3d → ルート → src/ → app.ts`。コミットのツリーが
**ルート**で、ファイルやフォルダーはクリックした行の名前を持ちます。どの項目を
クリックしても、そこへ戻れます。リビジョンを入力する、ref を選ぶ、**開く**の横の
例を選ぶ、のいずれかで新しいパスが始まります。

**戻る**と**進む**はブラウザーのように、開いたものすべてをたどります。戻った後は
「進む」で先へ戻れますが、そこから新しいものを開くまでです。リビジョン欄は歩みに
ついてくるので、`main:src/app.ts` はいつでもコピーできます。

### 色

種類ごとの色は、どこに出ても同じです — バッジ、パスの項目、カード、行: コミットは
テーマのアクセント色、ツリーは黄色、blob は青、タグと ref は緑。オブジェクトの
見出しの下には、その種類が*何であるか*を一文で示します。

### モデルの中の現在地

ペインの下の帯は git の連なりです — **ref → commit → tree → blob**。注釈付き
タグでは ref と commit の間に **tag** が入ります。画面に出ている種類が*現在地*と
して強調されます。

## リビジョンの入力

入力欄は `git rev-parse` が受け付けるものなら何でも受け付けます。ここがこの画面が
ブラウザであることをやめ、学ぶための道具になる場所です。

| これを入力 | 得られるもの |
|-----------|--------|
| `HEAD` | 現在のコミット |
| `HEAD~3` | 3 つ前のコミット |
| `HEAD^{tree}` | そのコミットのツリー、皮をむいたもの |
| `HEAD:src/app.ts` | そのパスの blob を直接 |
| `v1.0^{}` | タグオブジェクトではなく、注釈付きタグが指している先 |
| `a1b2c3d` | sha による任意のオブジェクト — 短縮形も使えます |

ツリー一覧のモード数字は覚えておく価値があります。`100644` はファイル、`100755` は
実行可能ファイル、`040000` はサブツリー、`120000` はシンボリックリンク、`160000` は
サブモジュールの gitlink — 最後のものが、サブモジュールが保存している内容のすべて
です。

## 知っておくべき制限

- **読み取り専用なのは意図的です。** ここには書き込むための道具がありません。手で
  オブジェクトを作るのは `git hash-object` の練習であり、その居場所はターミナルです。
- **大きな blob は切り詰められます** — 最初の 200 KB まで。何であるかを見るには十分
  で、ウィンドウを固まらせるには足りない量です。
- **サイズは `git cat-file -s` が報告するオブジェクトの内容サイズ** であって、パック
  後のディスク上の消費量ではありません。そちらは
  [メンテナンス](maintenance.md) を参照してください。
- **到達不能なオブジェクトもオブジェクトです。** `git fsck` の dangling 報告から sha
  を貼り付ければ開けます。失われたコミットの中身を、復旧するかどうか決める前に確認
  する最短ルートになることがよくあります。
- **サブモジュールの行は開けません。** その gitlink は別リポジトリのコミットを
  指しており、このリポジトリにはありません。
- **件数とリンク先には上限があります。** サブフォルダーが 300 を超えるツリーでは
  件数なしで表示し、リンク先を示すのは最初の 50 個のシンボリックリンクだけです。
- **パスはダイアログと一緒に終わります。** 閉じると、次は HEAD のブランチから
  やり直しです。
