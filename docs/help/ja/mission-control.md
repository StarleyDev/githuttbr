# ミッションコントロール

リポジトリが 20 個あっても、疑問はいつも同じです。どれが自分を必要としているのか。

ミッションコントロールはそれに答えます。**アクティブなワークスペース** のすべての
リポジトリを 1 画面に並べ、本当に手を入れるべき順に並べます。

1. **停止中** — リベースやマージが途中で止まっている、コンフリクトしている、
   そもそも読めないリポジトリ。
2. **同期が必要** — まずプルすべきコミット、次にプッシュすべきコミット。
3. **作業中** — 未コミットの変更、追跡されていないファイル。
4. **きれい** — 静かなものたちは、いちばん下、いるべき場所へ。

![すべてのリポジトリを 1 画面に、ひどいものから順に](../../screenshots/mission-control.webp)

## 1 行が教えてくれること

各行は左から右へ読み、列はリスト全体で揃うので、件数を表のように比べられます。

| 列 | 内容 |
|---|---|
| **リポジトリ** | 名前、グループ、ブランチとその upstream。なければ琥珀色で **upstream なし**：誤ってプッシュされることはないが、同期もされない |
| **最新コミット** | 件名と作成者。開かなくても、そのリポジトリで最後に何をしていたかがわかる |
| **ローカル** | 競合 · ↓ プル待ち · ↑ プッシュ待ち · ステージ済み · 変更 · 未追跡 · スタッシュ。ホバーで何の件数かを表示 |
| **ホスティング** | オープン中のプルリクエスト（**あなた**のレビュー待ちのものは琥珀色）と、HEAD の CI。件数をクリックするとそのリポジトリの **プルリクエスト** ページが、**CI** をクリックするとその実行一覧が開きます |
| **リリース** | HEAD から到達できる最新のタグと、その後に続くコミットの数。ひとつもなければ **最新**。件数はリリースがどれだけ遅れているかで色分けされます：5 コミットまでは灰色、20 までは黄色、それを超えると赤。範囲は 4 つあり、カスタムカラーも含めて [**設定 → テーマ → リリース注記の色**](themes.md#リリース注記の色) で変更できます |
| **アクティビティ** | 14 日間のコミットのスパークラインと、その件数 |
| **時間** | 最後のコミットと、最後の**フェッチ**からの経過時間 |

ステータスアイコンにホバーすると、その行がその位置にある理由が表示されます —
「プッシュ待ち 2 件 · 未コミット 1 件」。

フェッチの経過時間を出すのは、このページを読んでもフェッチは行われないからです。
「プル待ち」の件数は最後のフェッチ時点のものです。upstream のあるブランチが 1 日以上
フェッチしていない、または一度もしていない場合は琥珀色になります — 0 を信じる前に
フェッチしてください。時刻は git 自身から読むので、ターミナルでの `git fetch` も
反映されます。

![設定 → Git と同期：自動フェッチの隣にある Mission Control の更新間隔](../../screenshots/settings-git-sync.webp)

ウィンドウが狭くてもすべての列が残り、表は枠の中で横にスクロールします。

行の末尾の **開く** は、そのリポジトリそのもの — グラフ — を表示します。そのタブが
最後に、PR の件数から開いたプルリクエスト一覧を表示していた場合でも同じです。

行を展開すると（シェブロン、または <kbd>space</kbd>）、プッシュ待ちのコミットが
どれで、どのファイルが汚れているかまで正確に見えます。

## 一覧をさばく

- 上部の状態ピルは **フィルタ** です。「停止中 3」をクリックすればそれだけが残ります。
  **オープンな PR N 件** と **CI 失敗 N 件** も同じように絞り込み、その下の行の
  **あなたのレビュー待ちの PR N 件** も同様です。
- **緊急度**、**名前**、**活動** で並べ替えられます。
- **複数のリポジトリにチェック** を入れてまとめてフェッチしたり、遅れているものだけを
  プルしたりできます（ボタンが対象の数を数えてくれます）。
- **古い N 件をフェッチ** は、upstream のあるブランチが 1 日以上フェッチしていないときに
  表示され、それだけをフェッチします — 「プル待ち」が間違っているかもしれないものです。
- 開いている間は 30 秒ごとに自分で更新します。間隔は **設定 → Git と同期 →
  Mission Control の更新間隔** で変えられます（最短 30 秒）。ページを閉じている間は
  何も動きません。

| キー | 動作 |
|---|---|
| <kbd>↑</kbd> <kbd>↓</kbd> または <kbd>j</kbd> <kbd>k</kbd> | 一覧を移動 |
| <kbd>Enter</kbd> | そのリポジトリを開く |
| <kbd>f</kbd> / <kbd>p</kbd> | フェッチ / プル |
| <kbd>space</kbd> | 展開する |
| <kbd>/</kbd> | フィルタへ移動 |

## これはタブではなく、ビューです

ワークスペース名の隣のゲージで開閉し、どれかのタブをクリックすれば作業に戻ります。
自分でタブを増やすことはなく、いま開いているワークスペースに属します。ワークスペースを
切り替えれば、そのワークスペースのダッシュボードになります。

git の側は **ローカル** です。リポジトリごとに git コマンドをいくつか走らせるだけで、
フェッチはしません。ホストと通信するのは **ホスティング** 列だけです。各リポジトリの
ホストに、オープン中のプルリクエストと HEAD の CI を、そのリポジトリのプロファイルで
静かに問い合わせます。そのプロファイルのトークンや連携がないホストは何も表示しない
だけで、サインインのウィンドウが開くことはありません。すでにタブで開いている
リポジトリは、サイドバーがそのプルリクエストを持っているので、呼び出しは発生しません。

数字を正しく読むための制限:

- ホストへの問い合わせは、更新間隔にかかわらず、リポジトリごとに **最大で 5 分に
  1 回** です（HEAD が動いたときや CI の実行が続いているときは早まります）。ホストの
  API の利用枠はアプリのほかの部分と共有されているからです。**更新** で今すぐ
  問い合わせ直します。
- ホストの最初のページが満杯で返ってきたとき、件数は **30+** と表示されます。
  一覧ページにはすべてあります。
- リリース列は **HEAD から到達できる** 最新のタグであり、リポジトリ内で最新のタグ
  ではありません。HEAD がすでに持っているコミットに作ったタグは、2 分以内に
  表示されます。

フェッチは常に、あなたが頼んだから起きます。
