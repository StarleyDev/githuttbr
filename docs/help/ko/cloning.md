# 클론

**새 저장소 → 클론**, 또는 `⌘K` → *클론*. URL을 붙여 넣거나, GitHub, GitLab,
Bitbucket, Azure DevOps에 로그인해 내 저장소 중에서 고르세요. 선택한
[프로필](profiles.md)의 토큰은 클론에 쓰인 뒤 버려지고, `.git/config`에는 결코
기록되지 않아요.

상위 폴더와 이름을 고르면, 입력란 아래 줄에 저장소가 정확히 어디에 놓일지 표시돼요.
이미 존재하는 폴더는 합쳐지지 않고 거부돼요.

## 여러 저장소를 한 번에

새 컴퓨터를 세팅하거나 팀이 가진 서비스를 전부 받아 오려면, 예전엔 저장소마다 이
대화상자를 한 번씩 열어야 했어요. 호스트 탭에서 원하는 저장소마다 체크박스를
체크하거나, **표시된 항목 모두 선택**으로 필터에 맞는 것을 전부 고르세요. 행을
클릭하면(체크박스가 아니라) 여전히 그 하나만 골라요.

두 개 이상 체크하면 대화상자는 모두를 같은 상위 폴더에, 각각 저장소 이름을 딴
폴더로 클론해요. 시작하기 전에 경로 목록이 표시돼요. 이름이 같은 두 저장소
(`org-a/app`과 `org-b/app`)는 한 폴더를 두고 다투는 대신, 둘 다 폴더 이름에
소유자가 붙어요(`org-a-app`, `org-b-app`).

![클론 대화상자의 GitHub 탭: 저장소 세 개가 체크되어 있고, 각각이 놓일 폴더가 상위 폴더 아래에 나열되며, 저장소 3개 클론 버튼이 보여요](../../screenshots/clone-multi-select.webp)

일괄 클론은 곧장 구석의 트레이로 가요. 한 번에 세 개씩 실행되고 나머지는
*대기 중*으로 기다려요. 각각에 취소 버튼이 따로 있어요. 각 저장소는 끝나는 대로
탭으로 열려요.

제한:
- 일괄 클론에서는 **체크아웃할 브랜치**가 숨겨져요. 브랜치 이름은 서로 다른 저장소
  사이에서 의미가 없으니, 각 저장소는 기본 브랜치를 받아요. 다른 고급 옵션(부분,
  얕은, 단일 브랜치, 서브모듈)은 모두에 적용돼요.
- 여러 개 선택은 호스트 탭에서만 돼요. URL 탭은 URL 하나만 받아요.
- 하나가 실패해도 나머지는 멈추지 않아요. 폴더가 이미 있는 저장소는 자기 오류로
  실패하고 나머지는 계속 진행돼요.

## 고급 — 클론 범위 좁히기

**고급** 아래의 모든 항목은 기본적으로 꺼져 있어요. 그대로 두면 평범하고 완전한
클론을 얻어요. 이 항목들이 값어치를 하는 건 "완전한"이 20분과 수 기가바이트를 뜻하는
저장소에서예요.

![고급을 펼친 클론 대화상자: 부분 클론, 얕은 클론, 단일 브랜치, 서브모듈, 그리고 브랜치 선택기](../../screenshots/clone-advanced.webp)

| 옵션 | git이 하는 일 | 대가 |
|--------|---------------|---------------|
| **부분 클론** | `--filter=blob:none` | 히스토리는 전부, 파일 내용은 없음. 블롭은 필요할 때 받아 오므로 오래된 파일을 열려면 네트워크가 필요해요. |
| **얕은 클론** | `--depth=N` | 가장 최근 N개의 커밋만 존재해요. blame, log, bisect, range-diff가 그 절단면에서 멈춰요. |
| **브랜치 하나만** | `--single-branch` | 다른 브랜치들은 페치할 때까지 원격에 남아 있어요. |
| **서브모듈도 클론** | `--recurse-submodules` | 모든 서브모듈까지 체크아웃돼요. 지금은 시간이 더 들지만, 나중에 빠진 디렉터리가 없어요. |
| **체크아웃할 브랜치** | `--branch <name>` | 원격의 기본 브랜치 대신 그 브랜치에서 시작해요. |

**얕은 것보다 부분이 먼저예요.** 부분 클론은 모든 커밋을 유지하므로 히스토리는 계속
검색할 수 있고, 파일 내용만 필요할 때 가져와요. 얕은 클론은 실제로 히스토리를 버려요.
`git log`가 절단면에서 끝나고 blame은 그 너머를 보지 못해요. 안에서 작업하려고
모노레포를 클론하는 거라면 대개 부분 클론이 원하는 쪽이에요.

얕은 클론은 되돌릴 수 있어요. [터미널](terminal.md)에서 `git fetch --unshallow`를
실행하면 히스토리가 다시 채워져요.

### 브랜치 고르기

브랜치 이름을 입력하거나, **브랜치 목록 보기**를 눌러 원격에 무엇이 있는지 물어보고
(`git ls-remote --heads`) 드롭다운에서 고르세요. 네트워크 왕복은 한 번뿐이고, 버튼을
누를 때만 일어나요. 입력하는 동안에는 아무것도 조회하지 않아요.

목록 조회가 실패하면 — 아직 토큰이 없는 비공개 URL, 오타, 네트워크 없음 — 그 항목은
그냥 텍스트 입력란으로 남고, 실제 오류는 클론 자체가 알려 줘요.

### 플래그에 대한 두 가지 메모

- **`--depth`는 `--single-branch`를 함축해요.** 얕은 클론에서 *브랜치 하나만*을
  체크하지 않은 채 두는 것이 곧 다른 브랜치들을 다시 요청하는 일(`--no-single-branch`)
  이고, 그래서 그 아래 안내 문구가 바뀌어요.
- **로컬 폴더를 클론할 때**는 보통 `--depth`가 완전히 무시돼요. git이 가져오는 대신
  객체 저장소를 하드링크하거든요. 로컬 저장소의 얕은 사본을 요청하면 Gitcito는
  `file://` URL을 통해 클론해서, 요청한 깊이가 실제로 얻는 깊이가 되게 해요.

## 진행 상황, 백그라운드, 취소

막대는 git이 보고하는 것을 그대로 보고해요. 세는 중, 압축 중, 받는 중, 해석 중,
체크아웃 중. 전체량을 보고할 수 없는 단계에서는 가짜 백분율 대신 진행 정도를 알 수 없는
막대가 표시돼요.

큰 클론은 몇 분이 걸리는데, 예전엔 대화상자 밖을 잘못 클릭하기만 해도 그 시간을
전부 잃었어요. 이제는 대화상자를 닫아도 — **백그라운드에서 실행**, `Esc`, ✕, 바깥
클릭 — 숨겨질 뿐이에요. 클론은 계속 진행되고, 같은 진행 막대를 단 작은 카드가 되어
아래 구석으로 옮겨 가요. 그동안 다른 클론을 시작할 수도 있고, 각각 자기 카드를 받아요.

![아래 구석의 클론 트레이: 받는 중, 해석 중, 세는 중인 클론 세 개와 대기 중인 네 번째, 각각 취소 버튼이 있어요](../../screenshots/clone-tray.webp)

저장소를 잘못 골랐나요? 대화상자의 **클론 취소**나 카드의 ✕를 누르면 git을 멈추고
반쯤 쓰인 폴더를 지워요. 그 밖에는 아무것도 건드리지 않아요. 그 폴더가 클론 시작
전에는 없었다는 걸 처음에 확인해 두니까요. 취소한 클론은 이어서 할 수 없고, 다시
시작하면 처음부터 시작해요.

끝나면 대화상자가 아직 열려 있든 아니든, 새 저장소가 탭으로 열리고 클론에 사용한
프로필에 고정돼요.

클론은 앱 안에서 실행되므로 Gitcito를 종료하면 멈춰요. 종료는 정리를 기다리지 않아서
반쯤 쓰인 폴더가 남을 수 있어요. 대화상자는 이미 있는 폴더를 거부하니, 그곳에 다시
클론하기 전에 지워 주세요.
