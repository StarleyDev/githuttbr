# 객체 탐색기

git은 복잡하다는 평판이 있어요. 그 평판의 거의 전부는 모델을 한 번도 본 적이
없다는 데서 와요. **네 가지 객체, 그리고 포인터**가 전부인데 말이죠. 커밋을
클릭해 그 트리로 내려가고, 내 파일이 사실은 트리가 이름을 붙여 준 블롭*이라는*
것을 확인하고 나면, 포슬린 명령들은 더 이상 마법이 아니게 돼요.

`⌘K` → **객체 탐색기**. 이 화면은 단 1바이트도 바꿀 수 없어요 — 뒤에서
일어나는 호출은 전부 읽기예요.

![main이 가리키는 커밋: 브랜치에서 온 경로, 가리키는 대상, 모델에서 커밋의 자리](../../screenshots/objects.webp)

## 네 가지 객체

| 객체 | 무엇인가 | 무엇을 아는가 |
|--------|----|-------|
| **blob** | 파일의 *내용* | 아무것도 몰라요. 이름도, 경로도, 히스토리도 |
| **tree** | 디렉터리 목록 | 이름, 모드, 그리고 자식 blob이나 tree 각각의 sha |
| **commit** | 스냅샷 하나 | 자기 트리, 부모들, 작성자, 커미터, 메시지 |
| **tag** | 주석 달린 태그 | 가리키는 객체, 태그를 단 사람, 메시지 |

대부분의 사람이 놀라는 건 첫 번째 줄이에요. **블롭에는 이름이 없어요.**
히스토리 어디에 있든 내용이 같은 두 파일은 같은 블롭이고, 한 번만 저장돼요.
이름은 그것을 가리키는 트리에 있어요 — git이 파일이 아니라 내용을 추적하는
이유, 그리고 이름 변경이 기록되는 게 아니라 탐지되는 이유가 바로 이거예요.

**ref** — `refs/heads/main`, `refs/tags/v1.0`, `HEAD` — 는 sha 하나가 들어 있는
파일일 뿐이에요. "브랜치는 싸다"는 말의 전부가 이것이에요.

## 걸어 다니기

![커밋에서 src/까지: 폴더가 먼저, 모드마다 뜻을 글로 표시](../../screenshots/objects-tree.webp)

왼쪽 열은 git이 묶는 방식 그대로 모든 ref를 보여 줍니다: HEAD(브랜치 위에
있으면 `→ main`과 함께), 브랜치, 태그, 원격. 그룹마다 개수가 붙고, 원격은 접힌
상태로 시작합니다. 네모 표시는 커밋을 가리키는 ref, 둥근 초록 표시는 **주석**
태그입니다. 필터는 모든 그룹을 한꺼번에 좁힙니다. ref를 클릭하면 그것이 가리키는
객체로 가고, 거기서 걸어가는 동안 그 행은 강조된 채로 남습니다.

거기서부터는 모든 것이 문입니다:

- **커밋**은 무엇을 **가리키는지** 보여 줍니다 — 항목 수가 붙은 루트 트리와 제목이
  붙은 각 부모 — 이어서 작성자와 커미터(같으면 *작성자와 같음*), 그리고 메시지.
- **트리**는 이름·모드·객체·크기 표이며 폴더가 먼저 옵니다. 모드마다 뜻이 글로
  붙습니다: *파일*, *실행 파일*, *폴더*, *심볼릭 링크*, *서브모듈*. 폴더는 항목
  수를, 심볼릭 링크는 가리키는 곳을 보여 줍니다.
- **blob**은 줄 번호와 함께 텍스트를 보여 주고(큰 것은 앞부분만), 바이너리면
  그렇다고 분명히 말합니다. 트리를 거쳐 왔다면 거기서의 이름을 알려 주는 막대가
  나옵니다 — *커밋 07c6f3d에서 src/app.ts(이)라는 이름, 모드 100644 (일반 파일)* —
  파일 히스토리로 가는 링크도 함께.
- **주석 태그**는 이름 붙인 객체를 가리키고 태그 작성자를 기록합니다.

![blob, 트리가 붙여 준 이름, 그리고 모델에서의 자리](../../screenshots/objects-blob.webp)

### 경로

리비전 입력란 아래의 띠가 지나온 **경로**입니다:
`브랜치 main → 커밋 07c6f3d → 루트 → src/ → app.ts`. 커밋의 트리가 **루트**이고,
파일이나 폴더는 클릭한 행의 이름을 받습니다. 아무 항목이나 클릭하면 그곳으로
돌아갑니다. 리비전을 입력하거나, ref를 고르거나, **열기** 옆의 예시를 고르면 새
경로가 시작됩니다.

**뒤로**와 **앞으로**는 브라우저처럼 연 것 전부를 오갑니다: 뒤로 간 뒤에는
앞으로가 다시 데려가지만, 거기서 새것을 열면 그때까지입니다. 리비전 입력란은 걸음을
따라가므로 `main:src/app.ts`를 언제든 복사할 수 있습니다.

### 색

종류마다 어디에 나오든 색이 하나입니다 — 배지, 경로 항목, 카드, 행: 커밋은 테마의
강조색, 트리는 노랑, blob은 파랑, 태그와 ref는 초록. 객체 머리글 아래에는 그 종류가
*무엇인지* 한 문장으로 적혀 있습니다.

### 모델에서 현재 위치

창 아래쪽 띠는 git의 사슬입니다 — **ref → commit → tree → blob**, 주석 태그라면
ref와 commit 사이에 **tag**가 들어갑니다. 화면의 종류가 *현재 위치*로 강조됩니다.

## 리비전 입력하기

입력란은 `git rev-parse` 가 받아들이는 것이면 무엇이든 받아요. 이 도구가 단순한
탐색기이길 그만두고 배우는 수단이 되는 지점이 여기예요:

| 이렇게 입력하면 | 이런 것이 나와요 |
|-----------|--------|
| `HEAD` | 현재 커밋 |
| `HEAD~3` | 세 커밋 이전 |
| `HEAD^{tree}` | 그 커밋의 트리를 벗겨 낸 것 |
| `HEAD:src/app.ts` | 그 경로의 블롭을 곧바로 |
| `v1.0^{}` | 태그 객체가 아니라, 주석 달린 태그가 가리키는 것 |
| `a1b2c3d` | sha로 지정한 아무 객체 — 축약형도 통해요 |

트리 목록의 모드 숫자는 알아 둘 만해요. `100644` 는 파일, `100755` 는 실행
파일, `040000` 은 하위 트리, `120000` 은 심볼릭 링크, `160000` 은 서브모듈
gitlink예요 — 마지막 그것이 서브모듈이 저장하는 것의 전부고요.

## 알아둘 만한 한계

- **일부러 읽기 전용이에요.** 여기에는 쓸 수 있는 도구가 없어요. 객체를 손으로
  만드는 건 `git hash-object` 연습이고, 터미널에서 할 일이에요.
- **큰 블롭은 잘려요** — 처음 200 KB까지만요. 그게 무엇인지 보기에는 충분하고,
  창을 멎게 하기에는 모자란 양이죠.
- **크기는 `git cat-file -s` 가 보고하는 객체의 내용 크기**이지, 팩으로 묶인 뒤
  디스크에서 드는 비용이 아니에요. 그건
  [유지 보수](maintenance.md)를 보세요.
- **도달 불가 객체도 여전히 객체예요.** `git fsck` 의 dangling 보고에서 sha를
  복사해 붙여 넣으면 열려요. 잃어버린 커밋에 무엇이 들어 있었는지, 복구할지
  결정하기 전에 확인하는 가장 빠른 방법인 경우가 많아요.
- **서브모듈 행은 열리지 않습니다.** 그 gitlink는 다른 저장소의 커밋을 가리키며,
  이 저장소에는 그 커밋이 없습니다.
- **개수와 링크 대상에는 상한이 있습니다.** 하위 폴더가 300개를 넘는 트리는 개수
  없이 보여 주고, 대상을 보여 주는 심볼릭 링크는 처음 50개뿐입니다.
- **경로는 대화 상자와 함께 끝납니다.** 닫으면 다음에는 HEAD의 브랜치부터 다시
  시작합니다.
