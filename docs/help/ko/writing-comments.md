# 댓글 쓰기

GitHub에 보내는 댓글은 Markdown이고, 아무 기능 없는 텍스트 상자에서는 `**`와
`- [ ]`를 모두 손으로 입력한 뒤 표가 제대로 나왔는지 브라우저에서 확인해야
합니다. 호스트에 쓰는 앱의 모든 입력란이 이제 같은 편집기이며, GitHub 자체 댓글
입력란과 같은 도구를 갖추고 있습니다.

- 풀 리퀘스트의 댓글 입력란, 스레드 답글, 줄 댓글
  ([풀 리퀘스트 페이지](pull-requests.md));
- 이슈의 댓글 입력란;
- 새 풀 리퀘스트의 설명과 새 이슈의 본문
  ([호스팅과 풀 리퀘스트](hosting.md)).

![풀 리퀘스트의 댓글 입력란. 서식 도구 모음과 “@al”에서 열린 멘션할 사람 목록](../../screenshots/comment-editor.webp)

## 작성과 미리 보기

**미리 보기**는 앱의 나머지 부분과 같은 Markdown 렌더러로, 표시될 모습 그대로
텍스트를 그립니다. 읽기 전용입니다. **작성**으로 돌아가면 텍스트와 커서가 떠날
때 그대로 있으므로, ⌘/Ctrl+Z로 보기 전에 입력한 내용을 여전히 되돌릴 수 있습니다.

탭은 탭 목록입니다. 하나에 포커스가 있을 때 ←와 →로 전환합니다.

## 도구 모음

| 도구 | 단축키 | 하는 일 |
|---|---|---|
| **제목** | — | 선택한 줄에 H1, H2, H3을 적용하는 메뉴. 줄이 이미 가진 수준을 고르면 제거됩니다 |
| **굵게** | ⌘/Ctrl+B | `**텍스트**` |
| **기울임꼴** | ⌘/Ctrl+I | `_텍스트_` |
| **코드** | ⌘/Ctrl+E | 줄 안에서는 `` `코드` ``, 선택이 여러 줄이면 ```` ``` ````로 감싼 블록 |
| **링크** | ⌘/Ctrl+K | `[텍스트](url)` — 선택한 URL은 주소가 되고, 다른 텍스트는 레이블이 됩니다 |
| **인용** | — | 선택한 각 줄에 `> ` |
| **글머리 기호 목록** | ⌘/Ctrl+Shift+8 | 선택한 각 줄에 `- ` |
| **번호 매기기 목록** | ⌘/Ctrl+Shift+7 | 선택한 각 줄에 `1. `, `2. `… |
| **작업 목록** | — | 선택한 각 줄에 `- [ ] ` |

모든 도구는 토글입니다. 이미 그 서식이 있는 텍스트에 적용하면 제거합니다. 아무것도
선택하지 않았을 때 굵게, 기울임꼴, 코드, 링크는 자리 표시 텍스트를 넣고 선택해서
바로 덮어쓸 수 있게 합니다. 목록 도구는 다른 종류의 목록 위에 겹치지 않고 그것을
바꿉니다.

편집은 텍스트 필드 자체의 편집으로 처리되므로, **⌘/Ctrl+Z로 도구 적용도
되돌립니다**. 입력한 단어와 똑같이, 다시 실행으로 돌아옵니다.

도구 모음은 Tab에서 한 번만 멈추며, ← →로 버튼 사이를 이동하고 ↓로 제목 메뉴를
엽니다. 댓글 입력란 안에서는 ⌘/Ctrl+K가 명령 팔레트를 여는 대신 링크를 만듭니다.
Mac에서는 단축키가 ⌘만 쓰므로, Ctrl+B, Ctrl+E, Ctrl+K는 macOS 텍스트 필드에서
하던 일을 그대로 합니다. 글자가 라틴 문자가 아닌 키보드 배열에서는 단축키가 물리적
B, I, E, K 키를 따릅니다.

## 목록

목록 항목 끝에서 **Enter**를 누르면 다음 항목이 시작됩니다 — 같은 기호, 다음 번호,
작업이면 빈 `- [ ]` — 들여쓰기도 그대로입니다. 기호 뒤에 아무것도 없는 항목에서
Enter를 누르면 목록이 끝나고 기호가 지워집니다. Shift+Enter는 일반 줄바꿈입니다.

## 멘션과 참조

**@**를 입력하면 입력할수록 좁혀지는 짧은 사람 목록이 열립니다. **#**는 풀
리퀘스트와 이슈를 번호와 제목으로 나열합니다(`#42`, 또는 제목의 단어라면
`#검색어`). ↑ ↓로 고르고, Enter나 Tab으로 넣고, Esc로 목록을 닫습니다 — 목록만
닫고, 입력란이나 주변 대화 상자는 닫지 않습니다.

목록은 호스트에 다시 묻지 않고 앱이 이미 가진 것에서 만듭니다.

| 입력란 | @ 후보 | # 후보 |
|---|---|---|
| 풀 리퀘스트 | 작성자, 리뷰어, 담당자, 댓글을 단 모든 사람 | 사이드바에 불러온 저장소의 열린 풀 리퀘스트와 이슈 |
| 이슈 | 작성자, 담당자, 댓글 단 사람 | 같음 |
| 새 풀 리퀘스트 | 리뷰어와 담당자 선택기가 읽는 사람, 불러온 풀 리퀘스트의 작성자 | 같음 |
| 새 이슈 | 불러온 풀 리퀘스트와 이슈의 작성자 | 같음 |

단어 안의 **@**나 **#**(이메일 주소), 제목의 `#`, 코드 안의 모든 것은 건드리지
않습니다.

## 보내기

⌘/Ctrl+Enter는 모든 입력란에서 보냅니다: 풀 리퀘스트나 이슈 댓글, 스레드 답글, 줄
댓글, 새 이슈의 설명. 입력란뿐 아니라 탭, 도구 모음, 미리 보기에서도 동작합니다.
Esc는 같은 곳에서 줄 댓글을 취소합니다. **스레드 답글**은 한 줄 입력란이므로 긴
대화에서 스레드마다 도구 모음이 늘어나지 않습니다. Enter로 보내고, Shift+Enter는 줄을
추가하며(입력란이 그만큼, 그리고 붙여 넣은 블록만큼 커집니다), Esc는 입력한 내용을 먼저
물어본 뒤 버립니다. 탭이나 도구 모음은 없지만 서식 단축키와 **@** / **#** 자동 완성은
동작하고, 보낼 내용이 생기면 **답글** 버튼이 나타납니다.

## 요약표

각 입력란 아래의 **Markdown 지원**은 그 자리에서 요약표를 엽니다: 각 서식, 그것을
위해 입력할 것, 단축키. Esc나 다른 곳을 클릭하면 닫힙니다. 쓰고 있는 내용은
움직이지 않습니다.

아래쪽의 **전체 가이드 열기**는 이 페이지를 엽니다. 핸드북은 별도의 탭이라 그리로
가면 입력란이 있는 페이지를 떠나게 되고, 보내지 않은 텍스트는 사라집니다. 그런
텍스트가 있으면 — 이 입력란이든 풀 리퀘스트 페이지의 다른 입력란이든 — 앱이 먼저
묻습니다. 새 풀 리퀘스트와 새 이슈 대화 상자에서는 핸드북이 대화 상자 뒤에 열리게
되므로, 요약표에 이 링크가 없습니다.

## 제한

- **첨부 파일 없음.** 파일을 끌어 놓거나 이미지를 붙여 넣어도 업로드되지 않습니다.
  GitHub에는 댓글 첨부 파일용 공개 API가 없어서 파일을 둘 곳이 없습니다. 웹사이트에서
  업로드하고 링크를 붙여 넣으세요.
- **이미 불러온 사람과 항목만.** @는 호스트의 사용자를 검색하지 않고, #도 모든
  이슈를 검색하지 않습니다 — 대화에 참여하지 않은 사람이나 사이드바가 읽지 않은 닫힌
  이슈는 후보에 나오지 않습니다. 그래도 이름이나 번호를 끝까지 입력할 수는 있습니다.
- **변경 제안, 저장된 답글, 이모지 선택기는 없습니다.**
- **미리 보기는 앱의 렌더러입니다.** 앱이 그리는 대로 Markdown을 보여 줍니다.
  호스트 자체의 표시는 세부적으로 다를 수 있습니다(GitHub 고유 확장, 링크로 바뀌는
  멘션).
- **미리 보기는 호스트가 아니라 앱의 그림입니다.** 풀 리퀘스트와 이슈 페이지에서 미리
  보기는 게시된 댓글이 앱에서 보일 모습대로 텍스트를 그립니다
  ([댓글이 표시되는 방식](pull-requests.md#댓글이-표시되는-방식)): 같은 엄격한 프로필, 유지되는
  줄바꿈, 클릭을 기다리는 다른 사이트의 이미지. GitHub에서는 게시된 댓글을 그 뒤에
  GitHub가 그리므로, 앱이 모르는 확장은 다르게 보일 수 있습니다. 새 풀 리퀘스트와 새
  이슈 대화 상자는 앱의 평소 Markdown 미리 보기를 씁니다.
- 단축키는 고정되어 있습니다: 단축키 설정에 없으며, 그곳에서 다시 지정해도 따르지
  않습니다.
