# 미션 컨트롤

저장소가 스무 개일 때, 질문은 늘 같아요. 어느 쪽이 나를 필요로 하지?

미션 컨트롤이 그 답을 줘요. **활성 작업 공간**의 모든 저장소를 한 화면에, 실제로
손이 필요한 순서대로 늘어놓아요.

1. **막힘** — 리베이스나 머지가 반쯤 끝난 채 남았거나, 충돌이 있거나, 아예 읽을 수
   없는 저장소.
2. **동기화 필요** — 먼저 풀할 커밋, 그다음 푸시할 커밋.
3. **작업 중** — 커밋하지 않은 작업, 추적되지 않는 파일.
4. **깨끗함** — 조용한 것들. 맨 아래, 있어야 할 자리에요.

![모든 저장소를 한 화면에, 급한 것부터](../../screenshots/mission-control.webp)

## 한 행이 알려 주는 것

각 행은 왼쪽에서 오른쪽으로 읽으며, 열이 목록 전체에서 정렬되어 개수를 표처럼
비교할 수 있습니다.

| 열 | 표시 내용 |
|---|---|
| **저장소** | 이름, 그룹, 브랜치와 그 upstream — 없으면 호박색 **upstream 없음**: 실수로 푸시될 일은 없지만 동기화도 되지 않음 |
| **마지막 커밋** | 제목과 작성자: 열지 않고도 저장소가 마지막으로 무엇을 했는지 |
| **로컬** | 충돌 · ↓ 풀 대기 · ↑ 푸시 대기 · 스테이징됨 · 수정됨 · 추적 안 됨 · 스태시. 마우스를 올리면 무엇을 세는지 표시 |
| **호스팅** | 열린 풀 리퀘스트(**내** 리뷰를 기다리는 것은 호박색)와 HEAD의 CI. 개수를 클릭하면 그 저장소의 **풀 리퀘스트** 페이지가, **CI**를 클릭하면 실행 목록이 열림 |
| **릴리스** | HEAD에서 닿는 가장 새로운 태그와 그 뒤에 쌓인 커밋 수 — 하나도 없으면 **최신**. 개수의 색은 릴리스가 얼마나 뒤처졌는지를 나타냄: 커밋 5개까지 회색, 20개까지 노랑, 그 이상은 빨강. 네 구간으로 나뉘며 [**설정 → 테마 → 릴리스 메모 색상**](themes.md#릴리스-메모-색상)에서 바꿀 수 있음 — 사용자 지정 색상 포함 |
| **활동** | 14일간의 커밋 스파크라인과 커밋 수 |
| **시간** | 마지막 커밋 이후, 그리고 마지막 **페치** 이후 경과 시간 |

상태 아이콘에 마우스를 올리면 그 행이 그 위치에 있는 이유가 표시됩니다 —
"2개 푸시 대기 · 1개 커밋 안 됨".

페치 경과 시간을 보여 주는 이유는 이 페이지를 읽어도 페치하지 않기 때문입니다.
"풀 대기" 수는 마지막 페치만큼만 최신입니다. upstream이 있는 브랜치가 하루 이상
페치하지 않았거나 한 번도 하지 않았다면 호박색이 됩니다 — 0을 믿기 전에 페치하세요.
시간은 git에서 직접 읽으므로 터미널의 `git fetch`도 반영됩니다.

![설정 → Git 및 동기화: 자동 페치 옆의 Mission Control 새로 고침](../../screenshots/settings-git-sync.webp)

창이 좁아도 모든 열이 남고, 표가 자기 테두리 안에서 옆으로 스크롤됩니다.

행 끝의 **열기**는 그 저장소 자체 — 그래프 — 를 보여 줍니다. PR 개수를 눌러 연 풀 리퀘스트 목록이 그 탭에 마지막으로 떠 있었더라도 마찬가지입니다.

행을 펼치면(꺾쇠, 또는 <kbd>space</kbd>) 정확히 어떤 커밋이 푸시를 기다리는지,
어떤 파일이 지저분한지 볼 수 있어요.

## 목록 다루기

- 위쪽의 상태 알약들은 **필터**예요 — "막힘 3개"를 누르면 그것만 보여요.
  **열린 PR N개**와 **CI 실패 N개**도 같은 식으로 거르고, 아래 줄의 **내 리뷰 대기
  PR N개**도 마찬가지예요.
- **긴급도**, **이름**, **활동** 순으로 정렬할 수 있어요.
- **저장소 여러 개를 체크**해서 페치하거나, 뒤처진 것만 골라 풀할 수 있어요
  (버튼이 개수를 세어 줘요).
- **오래된 N개 페치**는 upstream이 있는 브랜치가 하루 이상 페치하지 않았을 때 나타나며,
  그것만 페치합니다 — "풀 대기"가 틀렸을 수 있는 것들입니다.
- 열려 있는 동안 30초마다 스스로 새로 고쳐요 — **설정 → Git 및 동기화 → Mission
  Control 새로 고침**에서 바꿀 수 있고, 최소 30초예요. 페이지가 닫혀 있는 동안에는
  아무것도 실행되지 않아요.

| 키 | 동작 |
|---|---|
| <kbd>↑</kbd> <kbd>↓</kbd> 또는 <kbd>j</kbd> <kbd>k</kbd> | 목록 이동 |
| <kbd>Enter</kbd> | 그 저장소 열기 |
| <kbd>f</kbd> / <kbd>p</kbd> | 페치 / 풀 |
| <kbd>space</kbd> | 펼치기 |
| <kbd>/</kbd> | 필터로 이동 |

## 탭이 아니라 보기예요

작업 공간 이름 옆의 계기판이 이걸 켜고 꺼요. 아무 탭이나 누르면 하던 일로
돌아가요. 자기 탭을 따로 만들지 않고, 지금 있는 작업 공간에 속해요 — 작업 공간을
바꾸면 그 작업 공간의 대시보드가 나와요.

git 쪽은 **로컬이에요**: 저장소마다 git 명령 몇 개이고, 페치는 없어요. 호스트와
통신하는 건 **호스팅** 열 하나뿐이에요. 각 저장소의 호스트에 열린 풀 리퀘스트와
HEAD의 CI를 그 저장소의 프로필로, 조용히 물어요. 그 프로필에 토큰이나 연결이 없는
호스트는 그냥 아무것도 보여 주지 않고, 로그인 창은 절대 열리지 않아요. 이미 탭에
열려 있는 저장소는 호출하지 않아요. 사이드바가 이미 그 풀 리퀘스트를 갖고 있으니까요.

숫자를 제대로 읽기 위한 한계:

- 호스트에는 새로 고침 간격과 상관없이 저장소마다 **최대 5분에 한 번** 물어요(HEAD가
  움직였거나 CI 실행이 아직 진행 중이면 더 빨리). 호스트의 API 허용량은 앱의 나머지
  부분과 함께 쓰기 때문이에요. **새로 고침**을 누르면 지금 다시 물어요.
- 호스트의 첫 페이지가 가득 차서 돌아오면 개수는 **30+**로 보여요. 목록 페이지에는
  전부 있어요.
- 릴리스 열은 저장소에서 가장 새로운 태그가 아니라 **HEAD에서 닿는** 가장 새로운
  태그예요. HEAD가 이미 가진 커밋에 만든 태그는 2분 안에 나타나요.

페치는 언제나 여러분이 요청했을 때만 일어나요.
