# Центр управления

Двадцать репозиториев, и вопрос всегда один и тот же: какому из них я нужен?

Центр управления на него отвечает. Все репозитории **активного рабочего
пространства** на одном экране, упорядоченные по тому, кто действительно требует
внимания:

1. **Заблокировано** — недоделанный ребейз или слияние, конфликты, репозиторий,
   который вообще не читается.
2. **Синхронизировать** — сначала коммиты на пул, потом коммиты на пуш.
3. **В работе** — незакоммиченная работа, неотслеживаемые файлы.
4. **Чисто** — тихие, внизу, где им и место.

![Все репозитории на одном экране, худшие сверху](../../screenshots/mission-control.webp)

## Что говорит строка

Каждая строка читается слева направо, а столбцы выровнены по всему списку, так
что счётчики сравниваются, как в таблице:

| Столбец | Что показывает |
|---|---|
| **Репозиторий** | Имя, группа, ветка и её upstream — или **нет upstream** янтарным: такую ветку не отправишь по ошибке, но она и не синхронизируется |
| **Последний коммит** | Тема и автор: чем репозиторий занимался в последний раз, без его открытия |
| **Локально** | Конфликты · ↓ к загрузке · ↑ к отправке · в индексе · изменённые · неотслеживаемые · stash. Наведите, чтобы увидеть, что считает каждый |
| **Хостинг** | Открытые pull request — те, что ждут **вашего** ревью, янтарным — и CI для HEAD. Нажмите на счётчик, чтобы открыть страницу **Pull request** этого репозитория, или на **CI**, чтобы открыть его запуски |
| **Релиз** | Самый новый тег, достижимый из HEAD, и сколько коммитов появилось после него — **актуально**, если ни одного. Цвет счётчика зависит от того, насколько отстаёт релиз: серый до 5 коммитов, жёлтый до 20, красный дальше, в четырёх диапазонах, которые можно изменить — включая свои цвета — в [**Настройки → Темы → Цвета заметки о релизе**](themes.md#цвета-заметки-о-релизе) |
| **Активность** | Спарклайн коммитов за 14 дней и их число |
| **Время** | Сколько прошло с последнего коммита и с последнего **fetch** |

Наведите на значок статуса, чтобы увидеть, почему строка стоит здесь —
«к отправке: 2 · без коммита: 1».

Возраст fetch здесь потому, что чтение этой страницы никогда не делает fetch:
счётчик «к загрузке» свеж ровно настолько, насколько свеж последний fetch. Если
ветка с upstream не делала fetch день или больше, или никогда, возраст становится
янтарным — сделайте fetch, прежде чем верить нулю. Время берётся из самого git,
поэтому `git fetch` в терминале тоже считается.

![Настройки → Git и синхронизация: обновление Mission Control рядом с автоматическим fetch](../../screenshots/settings-git-sync.webp)

В узком окне остаются все столбцы, а таблица прокручивается вбок внутри своей
рамки.

**Открыть** в конце строки показывает сам репозиторий — его граф, — даже если его
вкладка в последний раз показывала список pull request, открытый счётчиком PR.

Разверните строку (шевроном или <kbd>space</kbd>), чтобы увидеть, какие именно
коммиты ждут отправки и какие файлы грязные.

## Как работать со списком

- Плашки статусов сверху — это **фильтры**: нажмите «3 заблокировано», чтобы
  увидеть только их. **Открытых PR: N** и **CI с ошибкой: N** фильтруют так же,
  как и **PR ждут вашего ревью: N** в строке ниже.
- Сортировка по **срочности**, **имени** или **активности**.
- **Отметьте несколько репозиториев**, чтобы сделать им фетч, или сделайте пул
  только тем, что отстают (кнопка сама их посчитает).
- **Fetch устаревших: N** появляется, когда ветки с upstream не делали fetch день или
  больше, и выполняет fetch только для них — тех, где «к загрузке» может быть неверным.
- Пока открыт, он обновляет себя каждые 30 секунд — это меняется в
  **Настройки → Git и синхронизация → Обновление Mission Control**, не меньше
  30 секунд. Пока страница закрыта, ничего не выполняется.

| Клавиша | Действие |
|---|---|
| <kbd>↑</kbd> <kbd>↓</kbd> или <kbd>j</kbd> <kbd>k</kbd> | Идти по списку |
| <kbd>Enter</kbd> | Открыть этот репозиторий |
| <kbd>f</kbd> / <kbd>p</kbd> | Фетч / пул |
| <kbd>space</kbd> | Развернуть |
| <kbd>/</kbd> | Перейти к фильтру |

## Это вид, а не вкладка

Датчик рядом с названием рабочего пространства переключает его; клик по любой
вкладке возвращает вас к работе. Своей вкладки он никогда не заводит и
принадлежит тому пространству, в котором вы находитесь: смените рабочее
пространство — получите его панель.

Сторона git — **локальная**: несколько команд git на репозиторий, без fetch.
Столбец **Хостинг** — единственная часть, которая обращается к хосту. Он
спрашивает у хоста каждого репозитория открытые pull request и CI для HEAD — от
имени профиля этого репозитория и тихо: хост без токена или привязки для этого
профиля просто ничего не показывает, и окно входа никогда не открывается.
Репозиторий, уже открытый во вкладке, не стоит ни одного запроса: у боковой
панели его pull request уже есть.

Ограничения, чтобы правильно читать цифры:

- Хосты опрашиваются **не чаще раза в 5 минут** на репозиторий (раньше, если
  HEAD сдвинулся или запуск CI ещё идёт), каким бы ни был интервал обновления, —
  лимит API хоста общий с остальным приложением. **Обновить** спрашивает заново
  сразу.
- Счётчик показывает **30+**, когда первая страница от хоста пришла полной; на
  странице списка есть все.
- Столбец релиза — это самый новый тег, **достижимый из HEAD**, а не самый новый
  тег в репозитории. Тег, созданный на коммите, который уже есть в HEAD,
  появляется в течение двух минут.

Фетч всегда делается только по вашей просьбе.
