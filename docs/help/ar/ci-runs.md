# تشغيلات CI

دفعتَ، والآن تنتظر: تنتقل إلى المتصفح، وتجد المستودع، وتفتح Actions، وتجد
تشغيلك، وتفتح المهمة التي احمرّت، وتمرّر حتى نهاية السجل. **تشغيلات CI** تضع هذه
الدورة بجانب الشيفرة. صفحة واحدة تخبرك كيف كان أداء كل سير عمل مؤخرًا، وتسرد
تشغيلات البعيد من الأحدث إلى الأقدم، وتفتح التشغيل الفاشل مباشرةً على الاختبار
الذي انكسر — مع الملف والسطر، على بُعد نقرة من محررك. وأزرار إعادة تشغيله أو
إيقافه على البطاقة نفسها.

تتحدث الصفحة إلى واجهة API الخاصة بالمضيف نفسه، بالرمز المميز الذي أعطيته
لـ GitHuttBr من قبل. لا شيء يعمل على جهازك — لذلك، انظر
[التكامل المستمر المحلي](local-ci.md).

![صفحة تشغيلات CI: بطاقة لكل سير عمل مع آخر تشغيلاته، ومرشحا فشلت وقيد التشغيل، وتقدّم تشغيل جارٍ، وتشغيل فاشل مفتوح على الاختبار الذي انكسر وعلى مهامه](../../screenshots/ci-runs.webp)

## فتحها

**الأدوات ← تشغيلات CI…**، أو *تشغيلات CI* في لوحة الأوامر (⌘K). تُفتح الصفحة
على تبويب المستودع، مثل الويكي والرؤى، وتقرأ البعيد المسمّى `origin` — أو أول
بعيد حين لا يوجد `origin`.

## ما تعرضه الصفحة

| الجزء | ما هو |
|---|---|
| **بطاقات سير العمل** | بطاقة لكل سير عمل: ما الذي يطلقه، ونسبة نجاحه في آخر 10 تشغيلات منتهية (أخضر من 90 %، وكهرماني من 70 %، وأحمر دون ذلك)، وتلك التشغيلات مربعاتٍ ملوّنة — الأقدم في طرف، ليقع الأحدث بجانب «الآن» —، ومتوسط وقته، ثم إما أبطأ مهامه وإما كيف انتهى آخر تشغيل له. انقر بطاقة لتسرد تشغيلات ذلك السير وحده؛ وانقرها مجددًا لتعرضها كلها |
| **كل الفروع / الفرع الحالي** | كل تشغيل على البعيد، أو الفرع الذي سحبته فقط |
| **فشلت / قيد التشغيل** | مرشحات سريعة مع عدد التشغيلات التي سيُبقيها كلٌّ منها. تعدّ ما تتركه المرشحات الأخرى، فالعدد هو ما ستعرضه النقرة |
| **المرشح** | يحصر التشغيلات المحمّلة حسب العنوان أو سير العمل أو الفرع أو المؤلف أو الإيداع أو الحدث |
| **بطاقة تشغيل** | عنوان الإيداع (أو اسم سير العمل)، ثم الفرع، وسير العمل ورقم التشغيل، وما بدأه (دفع، طلب سحب، جدول، يدوي…)، ومن بدأه، والإيداع — انقر الإيداع لنسخه. وحين يكون التشغيل تابعًا لطلب سحب، يفتح **PR #n** صفحة طلب السحب ذاك. وفي الطرف الآخر: أين وصل، وكم استغرق، ومنذ متى |
| **تشغيل جارٍ** | *قيد التشغيل · الخطوة 3 من 5*، وشريط تقدّم، والوقت حتى الآن. الخطوة هي خطوة المهمة الجارية؛ وعلى مضيف بلا خطوات (GitLab، Forgejo) يعدّ المهام بدلًا منها |
| **الاختبار الفاشل** | يُفتح التشغيل الفاشل وحده، الأحدث أولًا، مع الاختبار الذي يسمّيه سجله: المهمة، والاختبار، والسطر الأول من الخطأ، و**المسار:السطر** — انقره، أو انقر *فتح في المحرر*، لتصل إلى ذلك السطر. القراءة نفسها التي في [تبويب الفحوص](hosting.md#تبويب-الفحوص) لطلب السحب |
| **المهام** | تحته، كل مهمة مع حالتها ومدتها، مجمّعةً حسب المرحلة حيث للمضيف مراحل (GitLab، Azure). *عرض الخطوات والسجل* يفتح خطوات المهمة ونهاية سجلها — في المهمة الفاشلة يكون حاضرًا دائمًا، وفي غيرها يظهر حين تشير إلى المهمة |
| **الخطوات** | كل خطوة من المهمة، مع حالتها ومدتها — يبلّغ عنها GitHub وAzure وForgejo؛ ولا خطوات في GitLab |
| **السجل** | نهاية سجل مهمة منتهية، بألوانه. لا يُجلب إلا آخر 512 كيلوبايت — حيث يكون الفشل — وتقول الصفحة متى أُسقطت البداية |

ما دام في الصفحة شيء في الطابور أو قيد التشغيل، تعيد القائمة سؤال المضيف كل 15
ثانية، ومعها مهام التشغيل المفتوح وكل تشغيل جارٍ — ومن هناك يأتي عدّ الخطوات؛
وتتقدّم المدد كل ثانية. وحين لا تأتي دقيقتان من الإجابات بجديد — تشغيل ينتظر
الموافقة على نشر، مثلًا —، تبطئ إلى مرة في الدقيقة، ثم تسرع من جديد حالما يتحرك
شيء. والقائمة التي انتهى كل ما فيها لا تسأل شيئًا حتى تضغط تحديث، ولا يُسأل شيء
ما دامت النافذة مخفية.

التشغيل الذي يرسله المضيف بلا عنوان — كل خط في GitLab، أو بناء مجدول في Azure —
يُسمّى بموضوع إيداعه حين يكون الإيداع في الرسم، مقروءًا من مستودعك المحلي بلا
كلفة؛ وإلا فبرقمه.

## إعادة التشغيل والإلغاء والبدء

| الزر | يظهر حين | ما يحدث |
|---|---|---|
| **إعادة الفاشلة** | فشل التشغيل أو أُلغي | لا يُعاد إلا تشغيل المهام التي لم تنجح |
| **إعادة التشغيل** (↻) | انتهى التشغيل، على GitHub — على البطاقة حين تشير إليها | تُعاد كل المهام |
| **فتح في المتصفح** | عند الإشارة إلى بطاقة | التشغيل على موقع المضيف |
| **إلغاء** | التشغيل في الطابور أو قيد التشغيل | يسأل أولًا: تُقاطع المهام الجارية ويضيع عملها |
| **تشغيل سير عمل** | يستطيع المضيف بدء واحد يدويًا | اختر سير العمل وفرعًا؛ فيبدأ كأن ذلك الفرع قد دُفع، ويظهر في القائمة بعد ثوانٍ |

ما يسمح به كل مضيف:

| المضيف | القائمة والمهام | الخطوات | السجل | إعادة الكل | إعادة الفاشلة | إلغاء | البدء يدويًا |
|---|---|---|---|---|---|---|---|
| **GitHub** (وEnterprise Server) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ — يحتاج سير العمل إلى مُطلِق `workflow_dispatch` |
| **GitLab** (والمُدار ذاتيًا) | ✓ — خطوط، ومهام حسب المرحلة | — | ✓ | — | ✓ (*Retry*) | ✓ | ✓ — يشغّل `.gitlab-ci.yml` على الفرع |
| **Azure DevOps** | ✓ — عمليات بناء، ومهام حسب المرحلة | ✓ (المهام الفرعية) | ✓ | — | ✓ | ✓ | ✓ — أي تعريف بناء للمستودع |
| **Forgejo / Gitea** | ✓ على الخوادم التي فيها API تشغيلات Actions | ✓ | ✓ حين يقدّمه الخادم لرمز مميز | — | — | — | — |
| **Bitbucket** | — | | | | | | |

## الشارات في الرسم

يظهر الـ CI نفسه شارةً صغيرة بجانب كل إيداع في الرسم: خضراء، أو حمراء، أو ساعة
ما دام يعمل. مرّر المؤشر فوقها لترى المهام؛ وانقرها لصفحة المضيف. تأتي الشارات
من:

| المضيف | المصدر |
|---|---|
| GitHub | تشغيلات الفحص للإيداع — أي CI يبلّغ GitHub، لا Actions وحدها |
| GitLab | حالات الإيداع، وهي تشمل كل مهمة في الخط. والمهمة اليدوية (نشر، مثلًا) لا تترك الشارة عالقة على الساعة |
| Azure DevOps | آخر 100 عملية بناء في المستودع، مطابَقةً حسب الإيداع |
| Forgejo / Gitea | الحالة المجمّعة للإيداع — Forgejo Actions وأي CI خارجي |
| Bitbucket Data Center | حالات البناء للإيداع |

كل إجابة تُحفظ — ومنها «لا CI هنا» — ولا يُسأل عن الإيداع مجددًا إلا حين يمكن أن
تكون إجابته قد تغيّرت: كل 45 ثانية ما دام يعمل، وكل 10 دقائق بعد انتهائه، وبتواتر
يقلّ شيئًا فشيئًا لإيداع لم يكن له CI قط. هكذا يبقى الرسم المزدحم ضمن حصة المضيف
في الساعة.

## الحدود

- **البطاقات لا تعرف إلا التشغيلات التي سردتها الصفحة.** وهي آخر 50 تشغيلًا
  لمرشح الفرع النافذ — وقد يُظهر سير عمل نادر التشغيل أقل من عشرة مربعات،
  والتبديل إلى الفرع الحالي يعيد حساب كل بطاقة. ويظهر أبطأ مهمة حالما تقرأ الصفحة
  مهام تشغيل منتهٍ ما (يكفي التشغيل الفاشل الذي تفتحه)؛ وحتى ذلك الحين تقول
  البطاقة كيف انتهى آخر تشغيل.
- **الاختبار الفاشل يُقرأ من نص السجل.** يُتعرّف على Vitest وJest وpytest؛ وأي
  مشغّل آخر، أو خطأ بناء، أو سجل مقطوع، يعرض قائمة المهام وحدها. والمسار الذي
  كتبه المشغّل خارج نسخة السحب لا يمكن فتحه.
- **PR #n يتوقف على ما يقوله المضيف.** لا يذكر GitHub طلب السحب إلا للتشغيلات
  من المستودع نفسه، لا من نسخة متفرعة؛ ويذكره GitLab لخطوط طلبات الدمج، وAzure
  لعمليات بناء PR. وتشغيلات Forgejo لا تحمل رابطًا.
- **السجل هو النهاية، وبعد انتهاء المهمة فقط.** يسلّم GitHub وForgejo سجل المهمة
  بعد انتهائها؛ وما دامت تعمل، تعرض الصفحة خطواتها وهي تتقدّم، لا مخرجاتها. أما
  GitLab وAzure فيقدّمان سجل المهمة الجارية حتى تلك اللحظة — أعد فتحه لتقرأ المزيد.
- **يحتاج الرمز المميز إلى وصول إلى CI.** يحتاج رمز GitHub الدقيق إلى
  *Actions: read* للسرد و*Actions: write* لإعادة التشغيل أو الإلغاء أو البدء؛
  ويحتاج الرمز الكلاسيكي إلى `repo`. ويحتاج رمز GitLab إلى `read_api` للسرد
  و`api` للأزرار. ويحتاج رمز Azure إلى *Build: read* (و*Build: read & execute*
  للأزرار)؛ ومن دونه تبقى الصفحة والشارات فارغة بدل أن تفشل.
- **شارات Azure لا تعود إلا 100 عملية بناء.** الإيداع الأقدم بلا شارة، وإن ظلت
  صفحة تشغيلات CI تسرد عملية بنائه.
- **إعادة التشغيل في Azure هي «إعادة محاولة الفاشلة».** تعمل على خطوط YAML ذات
  المراحل؛ وقد يرفضها الخط الكلاسيكي، فتعرض الصفحة إجابة المضيف.
- **بدء سير عمل لا يسأل عن مدخلاته.** يرفض المضيف سير عمل GitHub أو خط GitLab
  الذي له مدخلات إلزامية بلا قيمة افتراضية، برسالته الخاصة.
- **Forgejo للقراءة فقط، وعلى الخوادم الحديثة فقط.** خوادم Forgejo وGitea
  الأقدم ليس فيها API لسرد التشغيلات؛ فتقول الصفحة إن المضيف غير مدعوم، وتظل
  شارات الرسم تعمل عبر حالات الإيداع. والمستودع الذي لا يستطيع الرمز رؤيته يظهر
  خطأ وصول، لا «غير مدعوم».
- **لا صفحة تشغيلات لـ Bitbucket.** في Data Center يكون CI نظامًا خارجيًا
  (Jenkins، Bamboo…) لا يبلّغ إلا حالة — وتلك الحالة هي شارة الرسم. وPipelines في
  bitbucket.org غير مدعومة.
- **بعيد واحد.** تقرأ الصفحة `origin`؛ ولا تُسرد التشغيلات على البعيد الآخر
  لنسخة متفرعة.
