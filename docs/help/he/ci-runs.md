# הרצות CI

דחפתם, ועכשיו מחכים: עוברים לדפדפן, מוצאים את המאגר, פותחים את Actions, מוצאים את
ההרצה שלכם, פותחים את המשימה שהאדימה, גוללים לסוף היומן. **הרצות CI** מביא את
הלולאה הזו לצד הקוד. דף אחד מראה איך כל תהליך עבודה הסתדר לאחרונה, מציג את ההרצות
של השרת המרוחק מהחדשה לישנה, ופותח הרצה שנכשלה ישר על הבדיקה שנשברה — עם הקובץ
והשורה, במרחק לחיצה מהעורך שלכם. הכפתורים להריץ שוב או לעצור נמצאים על הכרטיס.

הדף מדבר עם ה־API של שרת האירוח עצמו, עם הטוקן שכבר נתתם ל־GitHuttBr. שום דבר לא
רץ אצלכם במחשב — בשביל זה, ראו [CI מקומי](local-ci.md).

![דף הרצות CI: כרטיס לכל תהליך עבודה עם ההרצות האחרונות שלו, המסננים נכשלו ורצות, ההתקדמות של הרצה פעילה, והרצה שנכשלה פתוחה על הבדיקה שנשברה ועל המשימות שלה](../../screenshots/ci-runs.webp)

## איך פותחים

**כלים ← הרצות CI…**, או *הרצות CI* בלוח הפקודות (⌘K). הדף נפתח על הלשונית של
המאגר, כמו הוויקי והתובנות, וקורא את השרת המרוחק בשם `origin` — או את הראשון, כשאין
`origin`.

## מה הדף מציג

| חלק | מה זה |
|---|---|
| **כרטיסי תהליכי עבודה** | כרטיס לכל תהליך עבודה: מה מפעיל אותו, שיעור ההצלחה שלו ב־10 ההרצות האחרונות שהסתיימו (ירוק מ־90 %, ענבר מ־70 %, אדום מתחת), ההרצות האלה כריבועים צבעוניים — הישנה בקצה אחד, כך שהחדשה עומדת ליד „עכשיו” —, הזמן הממוצע שלו, ואו המשימה האיטית ביותר שלו או איך נגמרה ההרצה האחרונה. לחיצה על כרטיס מציגה רק את ההרצות של תהליך העבודה הזה; לחיצה נוספת מציגה שוב את כולן |
| **כל הענפים / הענף הנוכחי** | כל הרצה בשרת המרוחק, או רק הענף שעשיתם עליו checkout |
| **נכשלו / רצות** | מסננים מהירים עם מספר ההרצות שכל אחד ישאיר. הם סופרים את מה שהמסננים האחרים משאירים, כך שהמספר הוא מה שלחיצה תציג |
| **סינון** | מצמצם את ההרצות שנטענו לפי כותרת, תהליך עבודה, ענף, מחבר, קומיט או אירוע |
| **כרטיס הרצה** | הכותרת של הקומיט (או שם תהליך העבודה), ואז הענף, תהליך העבודה ומספר ההרצה, מה הפעיל אותה (push, בקשת משיכה, תזמון, ידני…), מי הפעיל אותה והקומיט — לחיצה על הקומיט מעתיקה אותו. כשההרצה שייכת לבקשת משיכה, **PR #n** פותח את הדף של בקשת המשיכה הזו. בצד השני: איפה היא עומדת, כמה זמן לקחה ולפני כמה זמן |
| **הרצה פעילה** | *רץ · שלב 3 מתוך 5*, פס התקדמות והזמן עד כה. השלב הוא של המשימה שרצה; בשרת בלי שלבים (GitLab, Forgejo) הוא סופר משימות במקום |
| **הבדיקה שנכשלה** | הרצה שנכשלה נפתחת לבד, החדשה קודם, עם הבדיקה שהיומן שלה מזכיר: המשימה, הבדיקה, השורה הראשונה של השגיאה ו**נתיב:שורה** — לחצו עליו, או על *פתיחה בעורך*, כדי להגיע לשורה הזו. אותה קריאה כמו ב[לשונית הבדיקות](hosting.md#לשונית-הבדיקות) של בקשת משיכה |
| **משימות** | מתחת, כל משימה עם המצב והמשך שלה, מקובצות לפי שלב (stage) כשלשרת יש stages (GitLab, Azure). *לצפות בשלבים וביומן* פותח את השלבים של משימה ואת סוף היומן שלה — במשימה שנכשלה הוא תמיד שם, באחרות הוא מופיע כשמצביעים על המשימה |
| **שלבים** | כל שלב של משימה, עם המצב והמשך שלו — GitHub, Azure ו־Forgejo מדווחים עליהם; ב־GitLab אין שלבים |
| **יומן** | סוף היומן של משימה שהסתיימה, עם הצבעים. רק 512 ה־KB האחרונים נטענים — שם נמצא הכישלון — והדף אומר כשההתחלה הושמטה |

כל עוד משהו בדף ממתין בתור או רץ, הרשימה שואלת את השרת שוב כל 15 שניות, ואיתה את
המשימות של ההרצה הפתוחה ושל כל הרצה פעילה — משם מגיע מספר השלב; משכי הזמן מתקדמים כל
שנייה. כששתי דקות של תשובות לא מביאות שום דבר חדש — הרצה שמחכה לאישור פריסה, למשל —,
היא מאטה לפעם בדקה, ומאיצה שוב ברגע שמשהו זז. רשימה שבה הכול הסתיים לא שואלת כלום עד
שלוחצים רענון, ושום דבר לא נשאל כל עוד החלון מוסתר.

הרצה שהשרת שולח בלי כותרת — כל צינור של GitLab, בנייה מתוזמנת של Azure — מקבלת את
השם של נושא הקומיט שלה כשהקומיט נמצא בגרף, כפי שהוא נקרא מהמאגר המקומי שלכם בלי
עלות; אחרת, את המספר שלה.

## הרצה חוזרת, ביטול, התחלה

| כפתור | מופיע כש | מה קורה |
|---|---|---|
| **הרצה חוזרת לכשלונות** | ההרצה נכשלה או בוטלה | רק המשימות שלא עברו רצות שוב |
| **הרצה חוזרת** (↻) | ההרצה הסתיימה, ב־GitHub — על הכרטיס כשמצביעים עליו | כל המשימות רצות שוב |
| **פתיחה בדפדפן** | כשמצביעים על כרטיס | ההרצה באתר של השרת |
| **ביטול** | ההרצה בתור או רצה | שואל קודם: המשימות שרצות נקטעות והעבודה שלהן אובדת |
| **הרצת תהליך עבודה** | השרת מאפשר להתחיל אחד ידנית | בחרו את תהליך העבודה וענף; הוא מתחיל כאילו הענף הזה נדחף, ומופיע ברשימה כמה שניות אחר כך |

מה כל שרת מאפשר:

| שרת | רשימה ומשימות | שלבים | יומן | להריץ הכול שוב | להריץ שוב כשלונות | ביטול | התחלה ידנית |
|---|---|---|---|---|---|---|---|
| **GitHub** (ו־Enterprise Server) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ — תהליך העבודה צריך טריגר `workflow_dispatch` |
| **GitLab** (ובאירוח עצמי) | ✓ — צינורות, משימות לפי stage | — | ✓ | — | ✓ (*Retry*) | ✓ | ✓ — מריץ את `.gitlab-ci.yml` על הענף |
| **Azure DevOps** | ✓ — בניות, משימות לפי stage | ✓ (tasks) | ✓ | — | ✓ | ✓ | ✓ — כל הגדרת בנייה של המאגר |
| **Forgejo / Gitea** | ✓ בשרתים עם ה־API של הרצות Actions | ✓ | ✓ כשהשרת מגיש אותו לטוקן | — | — | — | — |
| **Bitbucket** | — | | | | | | |

## תגים בגרף

אותו CI מופיע כתג קטן ליד כל קומיט בגרף: ירוק, אדום, או שעון כל עוד הוא רץ. רחפו
מעליו כדי לראות את המשימות; לחצו כדי להגיע לדף של השרת. התגים מגיעים מ:

| שרת | מקור |
|---|---|
| GitHub | ה־check runs של הקומיט — כל CI שמדווח ל־GitHub, לא רק Actions |
| GitLab | הסטטוסים של הקומיט, שכוללים כל משימה בצינור. משימה ידנית (פריסה, למשל) לא משאירה את התג תקוע על השעון |
| Azure DevOps | 100 הבניות האחרונות של המאגר, מותאמות לפי קומיט |
| Forgejo / Gitea | הסטטוס המשולב של הקומיט — Forgejo Actions וכל CI חיצוני |
| Bitbucket Data Center | סטטוסי הבנייה של הקומיט |

כל תשובה נשמרת — כולל „אין כאן CI” — ועל קומיט שואלים שוב רק כשהתשובה שלו עשויה
להשתנות: כל 45 שניות כל עוד הוא רץ, כל 10 דקות אחרי שהסתיים, ופחות ופחות לקומיט שמעולם
לא היה לו CI. כך גרף עמוס נשאר בתוך המכסה השעתית של השרת.

## מגבלות

- **הכרטיסים מכירים רק את ההרצות שהדף הציג.** אלה 50 ההרצות האחרונות של מסנן הענף
  הפעיל — תהליך עבודה שרץ לעיתים רחוקות עשוי להציג פחות מעשרה ריבועים, ומעבר לענף
  הנוכחי מחשב מחדש כל כרטיס. המשימה האיטית ביותר מופיעה ברגע שהדף קרא את המשימות של
  הרצה כלשהי שהסתיימה (ההרצה שנכשלה שהוא פותח מספיקה); עד אז הכרטיס אומר איך נגמרה
  ההרצה האחרונה.
- **הבדיקה שנכשלה נקראת מתוך הטקסט של היומן.** Vitest, Jest ו־pytest מזוהים; כל
  מריץ אחר, שגיאת בנייה או יומן קטוע מציגים רק את רשימת המשימות. נתיב שהמריץ כתב מחוץ
  ל־checkout אי אפשר לפתוח.
- **PR #n תלוי במה שהשרת אומר.** GitHub מציין את בקשת המשיכה רק להרצות מאותו מאגר,
  לא מ־fork; GitLab מציין אותה לצינורות של merge request ו־Azure לבניות PR. להרצות
  של Forgejo אין קישור.
- **היומן הוא הסוף, ורק אחרי שמשימה הסתיימה.** GitHub ו־Forgejo מוסרים את היומן של
  משימה אחרי שהיא נגמרה; כל עוד היא רצה, הדף מראה את השלבים שלה מתקדמים, לא את הפלט
  שלה. GitLab ו־Azure מגישים את היומן של משימה פעילה עד כה — פתחו אותו שוב כדי לקרוא
  עוד.
- **הטוקן צריך גישה ל־CI.** טוקן GitHub מפורט (fine-grained) צריך *Actions: read*
  כדי להציג ו־*Actions: write* כדי להריץ שוב, לבטל או להתחיל; טוקן קלאסי צריך `repo`.
  טוקן GitLab צריך `read_api` כדי להציג ו־`api` בשביל הכפתורים. טוקן Azure צריך
  *Build: read* (ו־*Build: read & execute* בשביל הכפתורים); בלעדיו הדף והתגים נשארים
  ריקים במקום להיכשל.
- **תגי Azure מגיעים רק 100 בניות אחורה.** לקומיט ישן יותר אין תג, אף שדף הרצות CI
  עדיין מציג את הבנייה שלו.
- **ההרצה החוזרת של Azure היא „ניסיון חוזר לכשלונות”.** היא עובדת בצינורות YAML עם
  stages; צינור קלאסי עשוי לסרב, והדף מציג את התשובה של השרת.
- **התחלת תהליך עבודה לא שואלת על הקלטים שלו.** תהליך עבודה של GitHub או צינור של
  GitLab עם קלטי חובה בלי ערך ברירת מחדל נדחה על ידי השרת, עם ההודעה שלו.
- **Forgejo לקריאה בלבד, ורק בשרתים עדכניים.** לשרתי Forgejo ו־Gitea ישנים יותר אין
  API להצגת הרצות; הדף אומר שהשרת לא נתמך, ותגי הגרף ממשיכים לעבוד דרך סטטוסי
  הקומיטים. מאגר שהטוקן לא יכול לראות מוצג כשגיאת גישה, לא כ„לא נתמך”.
- **ל־Bitbucket אין דף הרצות.** ב־Data Center, ה־CI הוא מערכת חיצונית (Jenkins,
  Bamboo…) שרק מדווחת סטטוס — הסטטוס הזה הוא תג הגרף. Pipelines של bitbucket.org לא
  נתמך.
- **שרת מרוחק אחד.** הדף קורא את `origin`; הרצות בשרת המרוחק האחר של fork לא מוצגות.
