# עוזר האישורים

Gitcito מחזיק שלושה סוגי סוד שונים, ואנשים מניחים בצדק שהם דבר אחד:

| | מוחזק על ידי |
|---|---|
| טוקני API של מארחים — בקשות משיכה, בעיות, בדיקות CI | Gitcito, ב[מחזיק המפתחות של מערכת ההפעלה](security.md) שלכם |
| תעבורת `git@…` | [מפתח ה־SSH](ssh-keys.md) שלכם, דרך סוכן ה־ssh של המערכת |
| **תעבורת `https://`** | **עוזר האישורים של git עצמו** |

השלישי אינו נחשב לתכונה בעיני אף אחד עד שהוא משתבש, ואז הוא מייצר את שתי התלונות
הנפוצות ביותר ב־git: *למה זה שואל אותי שוב?* ו*למה זה עדיין שולח את הטוקן
ששללתי?*

`⌘K` ← **עוזר האישורים**.

![העוזר המוגדר, כללים לכל מארח, ואזהרת הקובץ הפשוט](../../screenshots/credentials.webp)

## על מה אתם מסתכלים

כל `credential.helper` מוגדר, בהיקף שממנו הוא מגיע — `system`, `global`, ואז
המאגר הזה. **העוזרים מוערמים**: git שואל כל אחד בתורו, ועוזר ברמת המאגר אינו
מחליף עוזר גלובלי.

כל אחד נבדק מול המחשב שלכם:

| דגל | פירושו |
|------|-------|
| **מוכן** | תוכנית העוזר קיימת ותרוץ |
| **לא מותקן** | מוגדר, אבל התוכנית חסרה — כל בקשה נופלת חזרה להקלדה ידנית |
| **סיסמאות בקובץ פשוט** | העוזר `store` (ראו למטה) |

**כללים למארחים מסוימים** מונה מקטעי `credential.<url>.*`. הם גוברים על ההגדרה
הרגילה עבור הכתובות שהם תואמים, והם בדרך כלל התשובה ל״למה המארח האחד הזה מתנהג
אחרת״.

## בחירת עוזר

| עוזר | לאן הסיסמה הולכת |
|--------|------------------------|
| `osxkeychain` | מחזיק המפתחות של macOS — מוצפן, לכל משתמש |
| `manager` | Git Credential Manager (Windows, חוצה פלטפורמות) |
| `wincred` | מנהל האישורים של Windows |
| `libsecret` | שירות הסודות של לינוקס (GNOME Keyring, KWallet) |
| `cache` | זיכרון, ל־15 דקות. שום דבר בדיסק |
| `store` | **קובץ פשוט בתיקיית הבית שלכם. לא מוצפן** |

Gitcito מציע את מה שבאמת מותקן במחשב הזה, מסמן את זה שמתאים למערכת ההפעלה שלכם,
ומאפיר את השאר.

**ההיקף משנה.** *לכל המאגרים* כותב לתצורה הגלובלית שלכם, וזה מה שאתם כמעט תמיד
רוצים; *למאגר הזה בלבד* מיועד למאגר החריג שמתאמת מול משהו אחר.

## העוזר `store`, וקובץ `~/.git-credentials`

`store` כותב שורות `https://user:password@host` אל `~/.git-credentials`, בטקסט
פשוט, בלי הצפנה מכל סוג. כל דבר שרץ בשמכם יכול לקרוא אותו: סקריפט, postinstall
של תלות, כל דבר.

אם הקובץ הזה קיים, העמוד הזה אומר זאת וסופר את הרשומות. הוא לעולם אינו מציג
אותן — המונה הוא כל הפואנטה, וקריאת התוכן כדי להציג אותו הייתה אותה טעות בדיוק.

אם מצאתם אחד ולא התכוונתם: בחרו כאן עוזר אמיתי, ואז מחקו את הקובץ והתאמתו שוב פעם
אחת.

## שכחת אישור שנשמר

כשטוקן נשלל או מוחלף, העוזר ממשיך למסור את הישן וכל דחיפה נכשלת עם 401 שאינו נוקב
בשם דבר. **שכחה** מבקשת מהעוזר המוגדר למחוק את הרשומה שלו למארח הזה —
`git credential reject`, שהיא הדרך המתועדת של git עצמו.

שום דבר לא נקרא בדרך: Gitcito לעולם אינו קורא ל־`git credential fill`, הפקודה
שהייתה מדפיסה סיסמה חיה לפלט הסטנדרטי.

הדחיפה הבאה תשאל אתכם פעם אחת, והעוזר ישמור את התשובה החדשה.

## באיזה חשבון דחיפה משתמשת

כל URL של דחיפה נבדק בנפרד. הרשאת כתיבה היא רק יכולת של הטוקן. חברות במאגר, כללי ענפים והרשאה לשנות קובץ מסוים אינם נבדקים. קריאה ציבורית יכולה להצליח בלי פרטי התחברות.

![בדיקת ההתחברות של ה־remote](../../screenshots/remote-sign-in.webp)

דחיפה יכולה להתחבר בכמה דרכים: הטוקן של פרופיל, התחברות של GitHub CLI שמקושרת לפרופיל,
ה־helper של git עצמו, סיסמה שנשכחה ב־URL של ה־remote, או מפתח SSH. כשהיא נדחית, קודם
צריך לדעת באיזו מהן היא השתמשה. לחצו לחיצה ימנית על remote בסרגל הצד ובחרו **בדיקת
התחברות…** (או *בדיקת התחברות של מאגרים מרוחקים* בלוח הפקודות). הבדיקה קובעת את פרטי
ההתחברות באותו אופן כמו דחיפה, ואז שואלת עליהם את השרת:

| היא מציגה | מאיפה זה מגיע |
|----------|--------------------|
| המקור, וה[פרופיל](profiles.md) שמאחוריו | אותו סדר עדיפויות שדחיפה מפעילה — הפרופיל שהמאגר מקושר אליו, אחרת הפעיל, אחרת ה־helper של git |
| החשבון | התשובה של השרת עצמו (`/user`), לא מה שהוקלד בהגדרות |
| ההרשאות | הכותרת `X-OAuth-Scopes` של GitHub; התיאור ש־GitLab נותן לטוקן שלו |
| מה הן מתירות | הרשאות טוקן שקשורות לכתיבה (`repo` ב־GitHub, ‏`write_repository` ב־GitLab), וב־GitHub האם אפשר לשנות את `.github/workflows` |

היא גם מסמנת פרטי התחברות שהשרת דוחה (שפג תוקפם או שבוטלו), חשבון מקושר שכבר לא
מחובר, וסיסמה ששמורה כטקסט גלוי ב־URL של ה־remote.

**מגבלות.** טוקן GitHub מפורט לא מציג את ההרשאות שלו, ולכן אם הוא יכול לדחוף מוצג
כלא ידוע עד שדחיפה מנסה. Forgejo מדווח על החשבון אבל לא על ההרשאות של הטוקן. Azure
DevOps ו־Bitbucket מוצגים רק עם מקור ופרופיל. remotes של SSH לא נבדקים, אבל
[מפתחות SSH](ssh-keys.md) מציג מה הסוכן מחזיק. הבדיקה שואלת את ה־helper של git בשקט:
helper שהיה צריך חלון התחברות נחשב ריק.

## סיסמה ששמורה ב־URL של ה־remote

שכפול ישן, או URL שהודבק מוויקי, עשויים לשאת את פרטי ההתחברות בתוך הכתובת:
`https://user:token@git.example.test/team/app.git`. **סיסמה ב־URL תמיד קודמת:** git
שולח אותה ולא שואל אף helper — לא את הטוקן של ה[פרופיל](profiles.md) של המאגר, לא את
GitHub CLI, לא את האחסון של git עצמו. כל עוד הטוקן עובד, זה בסדר, ו־Gitcito לא נוגע
בו: **הוא אף פעם לא מסיר סיסמה מ־URL בלי לשאול אתכם.** ברגע שהטוקן מבוטל או פג תוקפו,
כל fetch, ‏pull ו־push של המאגר הזה בלבד נכשלים עם *Invalid username or token* או
*Authentication failed*, בעוד שהמאגרים האחרים באותו פרופיל עובדים. והטוקן יושב כטקסט
גלוי ב־`.git/config` של המאגר.

![הסרת טוקן שמור מ־URL של remote](../../screenshots/remote-url-token.webp)

Gitcito קורא את כתובות ה־fetch וה־push של כל remote ואומר זאת בשלושה מקומות:

| איפה | מה רואים |
|-------|--------------|
| fetch, ‏pull או push שנכשלו | השגיאה מסבירה שה־URL של ה־remote מכיל סיסמה שמורה, עם **להסיר מה-URL…** |
| סרגל הצד | סמל מפתח צנוע בשורה של ה־remote: ה־URL שלו מכיל סיסמה שקודמת לטוקן של הפרופיל. אותה פעולה נמצאת בתפריט הלחיצה הימנית שלו |
| **בדיקת התחברות…** | ה־remote מציג את הסיסמה כמקור שלו, עם אותו כפתור |

הפעולה שואלת קודם. היא מוציאה את הסיסמה מכל ה־URLs של ה־remote הזה — ה־URL של fetch
וכל URL של push שמכיל סיסמה — ולא כותבת דבר מלבד `.git/config`. מה שקורה אחר כך תלוי
במה עוד יכול להתחבר:

| אחרי ההסרה | במה fetch ו־push משתמשים |
|---------------|-------------------------|
| לפרופיל של המאגר יש טוקן או חשבון מקושר לשרת הזה | בטוקן הזה — האישור לא אומר יותר |
| אין טוקן פרופיל, אבל ל־helper של git עצמו יש התחברות לשרת | בהתחברות של ה־helper |
| אף אחד מהם | בשום דבר: fetch ו־push נכשלים עד שתוסיפו טוקן. האישור אומר זאת קודם ומציע **להוסיף טוקן קודם**, שפותח את הגדרות ← אינטגרציות |

כשהיא התחילה מפעולה שנכשלה, היא מציעה **לנסות שוב**.

**אין ביטול, בכוונה.** ביטול היה כותב את הסוד בחזרה לקובץ כטקסט גלוי, וזה בדיוק מה
שהפעולה נועדה למנוע. אם הטוקן הישן עדיין עשוי לעבוד, בטלו אותו בשרת: הוא היה קריא לכל
מה שיכול היה לקרוא את תיקיית המאגר.

**מגבלות.**

- גם שם המשתמש נעלם (`https://git.example.test/…`), כמו כשמריצים `git remote set-url`
  ביד; האישור אומר זאת. שרת שצריך אותו ב־URL — טוקן Bitbucket Data Center בלי שם
  משתמש בפרופיל — צריך שתוסיפו אותו בחזרה עם **לערוך את ה-remote…**.
- שם משתמש לבדו (`https://user@host/…`) לא מסומן: git עדיין שואל את ה־helper על הסיסמה
  של המשתמש הזה, כך ששום דבר סודי לא שמור.
- כתובות SSH לא משתנות: `git@host:…` ו־`ssh://git@host/…` מציינים את שם ההתחברות
  ש־ssh משתמש בו, לא פרטי התחברות.
- הקידומת של remote helper (`persistent-https::https://…`, ‏`gcrypt::…`) נשמרת;
  ה־URL שאחריה נקרא ומנוקה כמו כל אחר.
- **כתובות דו־משמעיות לא מוצעות להסרה.** כשדרכי הקריאה לא מסכימות היכן מתחיל המארח —
  `@` אחרי `?` או `#` בכתובת, או סיסמה שמכילה `/` לא מקודד — חיתוך ב־`@` הלא נכון היה
  מפנה את ה־remote לשרת אחר. URL כזה מוצג רק מוסתר, וסמל המפתח פותח את **לערוך את
  ה-remote…** כדי שתתקנו אותו ביד.
- רק `.git/config` נקרא ומשתנה. URL שכלל `url.<base>.insteadOf` משכתב, או remote שמוגדר
  בתצורה הגלובלית שלכם, לא נבדק — ושינוי שם של remote אף פעם לא מעתיק לתצורה של המאגר
  סיסמה שכלל `insteadOf` מוסיף.
- הסיסמה אף פעם לא יוצאת מהתהליך הראשי: כתובות ה־remote מגיעות לחלון, לתפריט העתקת
  ה־URL ולחלון העריכה בלעדיה. שמירת חלון העריכה עם ה־URL שהוא הציג לא משנה דבר ושומרת
  את הסיסמה; **שינוי המארח או הנתיב משמיט אותה**, כי ה־URL שהקלדתם נכתב כמו שהוא. רק
  הפעולה הזו מסירה סיסמה תוך שמירת הכתובת.

## מגבלות ששווה להכיר

- **זה המחסן של git, לא של Gitcito.** שינוי שלו משנה גם את מה שהטרמינל שלכם עושה
  — וזו הפואנטה, ושווה לדעת את זה לפני שמשנים.
- **עוזרים ברמת המערכת מוצגים, לא ניתנים לעריכה.** הם חיים בתצורה שרק מנהל מערכת
  יכול לכתוב.
- **Gitcito אינו יכול למנות את מה שעוזר מחזיק.** שום API של אישורים לא חושף את
  זה בלי למסור את הסודות, ולכן החלון מדווח על התצורה ומוחק לפי בקשה, וזה הכול.
- **טוקן שנתתם ל־Gitcito הוא נפרד.** שלילה של אחד אינה נוגעת בשני; ראו
  [אבטחה](security.md) לצד של מחזיק המפתחות.
- **הטוקן של פרופיל נשאר מחוץ לסביבה של ה־hooks של המאגר.** hook רואה רק קוד לנקודת
  קצה פרטית, תקף כל עוד פקודת ה־git הזו רצה — מספיק ל־hook ששואל בכוונה, כמו
  ש־git-lfs עושה. ראו [הטוקן של פרופיל בזמן ש־git רץ](security.md#הטוקן-של-פרופיל-בזמן-שgit-רץ).
